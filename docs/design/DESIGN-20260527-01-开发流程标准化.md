## 1. 总体方案

将项目开发流程标准化为 skill + 模板 + git hook 的三层体系，AI 和人类共用同一套规范。

## 2. 模块划分

### 2.1 新增/修改文件

| 文件 | 类型 | 说明 |
|------|------|------|
| `skills/requirement-doc/SKILL.md` | 新增 | 需求文档 skill |
| `skills/requirement-doc/assets/requirement_template.md` | 新增 | 需求文档模板 |
| `skills/design-doc/SKILL.md` | 新增 | 方案设计 skill |
| `skills/design-doc/assets/design_template.md` | 新增 | 方案设计模板 |
| `skills/engineering-rules/SKILL.md` | 新增 | 工程规范 skill（已完成） |
| `docs/requirements/` | 新建 | 需求文档存档目录 |
| `docs/design/` | 新建 | 方案设计存档目录 |
| `.git/hooks/pre-commit` | 新增 | 提交前强制校验（已完成） |
| `.git/hooks/prepare-commit-msg` | 新增 | 前置检查提醒（已完成） |

### 2.2 模块职责

| 模块 | 输入 | 处理 | 输出 |
|------|------|------|------|
| requirement-doc skill | 主人需求描述 | 按模板填充 + 编号 | `docs/requirements/REQ-*.md` |
| design-doc skill | 需求文档 | 按模板填充 | `docs/design/DESIGN-*.md` |
| engineering-rules skill | 开发任务 | 前置读规范→改代码→后置校验 | 校验通过/失败 |
| pre-commit hook | git commit | 跑 check_engineering.sh | 允许/阻止提交 |

## 3. 开发流程

```
[主人提需求]
    ↓
[requirement-doc skill] 生成 REQ-*.md
    ↓
[design-doc skill] 生成 DESIGN-*.md
    ↓
主人确认方案
    ↓
[engineering-rules skill] 按规范改代码
  ├─ 前置：读 PROJECT_STATE.md + SKILL.md
  ├─ 编码中
  └─ 后置：跑 check_engineering.sh
    ↓
git add + commit
  └─ pre-commit hook 再跑 check_engineering.sh → 拦截 or 通过
    ↓
更新 PROJECT_STATE.md + MEMORY.md
```

## 7. 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 跳过需求文档直接要求写方案 | 报错：请先生成需求文档 |
| check 不通过 | 阻止 commit，列出具体失败项 |
| 紧急修复不想走全流程 | git commit --no-verify 绕过 |
