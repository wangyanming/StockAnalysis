# 方案设计：MySQL 连接池改造

**版本:** v1.1
**日期:** 2026-07-16
**关联需求:** REQ-20260716-01-MySQL连接池改造
**状态:** 已定稿（review 通过）

---

## 1. 总体方案

将 `utils/dao.py` 中 `DB` 类的单连接模式改为 `DBUtils.PooledDB` 连接池模式，消除多线程场景下单连接损坏导致全线崩溃的问题。对外接口完全兼容，所有调用方无需修改。

## 2. 模块划分

### 2.1 修改文件

| 文件 | 类型 | 说明 |
|------|------|------|
| `utils/dao.py` | 修改 | DB 类内部从单连接改为连接池，接口签名不变 |

**不修改 `requirements.txt`**：安装 `DBUtils` 由运维/部署环节处理，代码本身只新增一个 `import`，不引入外部破坏性依赖变更。

### 2.2 模块职责

| 组件 | 职责 |
|------|------|
| `DB.__init__` | 初始化连接池（`PooledDB` 实例），不再建立单连接 |
| `DB.execute` / `fetchone` / `fetchall` | **内部每次调用从池取连接** → 执行 → 自动归还 |
| `DB.close` | **保留，但不改变语义（仍关闭所有连接）**，因为单例模式下调用方不手动管归还，且 `close()` 后 DB 实例可重建 |
| `get_db()` | 仍返回 DB 单例实例，**调用方无需关心连接池逻辑** |

## 3. 关键设计决策（review 结论）

### 3.1 `self.conn` 不再缓存连接（🙅 不使用 @property 缓存 conn）
**v1.0 中的 `self.conn` property 改为每次调用 `execute/fetchone/fetchall` 时临时从连接池取连接。**

```python
# ❌ 错误方案：用 @property 缓存 conn
@property
def conn(self):
    if self._conn is None:
        self._conn = self._pool.connection()
    return self._conn

# ✅ 正确方案：每次方法调用从池取连接
def execute(self, sql, params):
    conn = self._pool.connection()   # 每次取新连接
    try:
        cur = conn.cursor()
        cur.execute(sql, params)
        return cur
    finally:
        conn.close()                 # 归还到连接池
```

原因：`self.conn` property 缓存的 conn 会被上一个请求用完后归还，下一个请求拿到同一个连接实例会出问题。**每次取新连接 + 用完立刻归还**才是线程安全的方式。

### 3.2 `close()` 保持原语义，不改为"归还连接"
**当前代码中很多调用方会显式调用 `db.close()`**（如 `_save_picks_to_db` 等）。如果 `DB` 是单例且 `close()` 只归还一条连接，语义会混乱。

改为连接池后：
- `DB.close()` **保持原逻辑：关闭全部连接池中的连接**（调用 `pool._connections` 清理）
- 调用方无需手动管理归还——**每次 `execute/fetchone/fetchall` 调用完毕，连接自动归还到池**
- `__enter__/__exit__` 上下文管理器也同理，`__exit__` 不额外操作（连接已自动归还）

### 3.3 DBUtils 安装检查
**先检查系统中是否已有 DBUtils**。只需 `pip3 install DBUtils`（~30KB，仅依赖 `pymysql`），无需修改 `requirements.txt`。

### 3.4 `maxusage=1000` 保留
保持参数配置，连接复用 1000 次后自动重建，防止连接因长期复用产生内存泄漏。

## 4. 数据流

```
                    ┌──────────────────────────┐
                    │  DB 实例 (单例)           │
                    │  ┌────────────────────┐  │
 get_db() ─────────►│  │ PooledDB(10,2)     │  │
                    │  │ ┌─conn1┐ ┌─conn2─┐ │  │
                    │  │ │ u1  │ │ u2    │ │  │
                    │  │ └─────┘ └───────┘ │  │
                    │  │ ┌─conn3┐ ┌─connN─┐ │  │
                    │  │ └─────┘ └───────┘ │  │
                    │  └────────────────────┘  │
                    └──────────────────────────┘
                              │
         每次 execute() 取连接 → cursor → 执行 → 自动归还
                              ▼
                     ┌──────────────────┐
                     │   MySQL Server    │
                     │ 127.0.0.1:3306    │
                     │ stock_analysis    │
                     └──────────────────┘
```

### 方法调用生命周期

```python
def fetchone(self, sql, params):
    conn = self._pool.connection()          # ① 从池取连接（如无空闲则阻塞等待）
    try:
        with conn.cursor() as cur:          # ② 创建 cursor
            cur.execute(sql, params)        # ③ 执行 SQL
            return cur.fetchone()           # ④ 返回结果
        # ⑤ cursor 自动 close
    finally:
        conn.close()                        # ⑥ 归还连接到池
```

## 5. 连接池参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `maxconnections` | 10 | 最大连接数，匹配 Web 服务并发需求 |
| `mincached` | 2 | 最小缓存数，启动时预热 |
| `blocking` | True | 无可用连接时阻塞等待（不抛异常） |
| `maxusage` | 1000 | 单连接复用上限，达到后自动重建 |
| `charset` | utf8mb4 | 字符集 |
| `autocommit` | True | 自动提交 |

## 6. 接口兼容性

### 6.1 所有对外接口签名不变

```python
db = get_db()                              # 返回 DB 单例（内部持有连接池）
db.execute(sql, params)                     # ✅ 不变
db.fetchone(sql, params)                    # ✅ 不变
db.fetchall(sql, params)                    # ✅ 不变
db.insert(table, data)                      # ✅ 不变
db.insert_or_ignore(table, data)            # ✅ 不变
db.executemany(sql, params_list)            # ✅ 不变
db.table_exists(table_name)                 # ✅ 不变
db.close()                                  # ✅ 保持原语义（关闭池中全部连接）
```

### 6.2 不会破坏的代码模式

- `db = get_db(); rows = db.fetchall(...)`
- `with get_db() as db: rows = db.fetchall(...)`
- `db.execute(...); cur = db.execute(...); cur.rowcount`
- 任何当前项目中调用 `get_db().xxx` 的地方

## 7. 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 单条连接损坏（`InterfaceError` / `Packet sequence number wrong`） | `execute()` 内自动重试 1 次：捕获异常 → `conn.close()`（丢弃旧连接）→ 重新 `pool.connection()` 取新连接 → 重试查询 |
| 连接池耗尽（`blocking=True`） | 阻塞等待至有可用连接，不抛异常 |
| 连接池初始化失败（`pool = PooledDB(...)` 时 MySQL 不可达） | 与现有行为一致，抛出异常+明确信息 |
| 查询重试仍然失败 | 抛出原始异常 + 附带 SQL 和参数信息 |
| DB.close() 后再次调用 | 连接池被关闭，重新初始化 |
