# 方案设计 — Web 前端原型技术方案

**版本:** v1.0
**日期:** 2026-07-16
**状态:** 待评审

---

## 1. 设计目标

基于已确认的产品原型（`web_prototype.html`），设计可直接接入真实后端 API 的 Web 前端页面，覆盖大盘概览、涨跌复盘、选股追踪三大模块。

| 模块 | 功能 | 数据来源 |
|------|------|---------|
| 大盘概览 | 指数看板、涨跌家数、成交额对比、板块 TOP10 双表 | `/api/market-overview` + `/api/market-summary` + `/api/sectors` |
| 涨跌复盘 | 涨停/跌停列表 + 分页 + 排序 | `/api/limit-up?date=` + `/api/limit-up/industry?date=` |
| 选股追踪 | 日期筛选 + 维度筛选 + 后续5日追踪 | 需新增后端 API |

---

## 2. 架构设计

### 2.1 技术选型

| 维度 | 选择 | 理由 |
|------|------|------|
| 服务端 | Python `ThreadingHTTPServer`（现有） | 零额外依赖，已有 HTTP 服务 |
| 前端 | 纯 HTML/CSS/JS 内联单文件 | 零 CDN 依赖，浏览器直接打开 |
| 数据格式 | JSON（现有） | 后端已支持 |
| 缓存 | 前端 `sessionStorage` + 后端 `_cached_call`（TTL 30s） | 减少重复请求 |
| 自动刷新 | `setInterval` 60s | 大盘数据时效性要求 |

### 2.2 文件结构

```
StockAnalysis/
├── web_server.py                          # HTTP 服务（不变）
├── docs/design/web_prototype.html         # 产品原型（mock 数据）
├── docs/design/web_app.html               # 真实接入版（最终交付）
└── (前端直接从 web_server.py 提供，不需要独立文件服务)
```

### 2.3 数据流

```
浏览器 ──GET /api/*──→ web_server.py ──MySQL/Sina──→ 数据源
     ←──JSON────────── ←──已格式化─────
```

前端不直接访问 MySQL 或外部 API，全部走 web_server.py 的 HTTP 网关。

### 4.3 数据加载策略

| 场景 | 策略 | 说明 |
|------|------|------|
| 页面首次加载 | 并发加载大盘概览所有 API | `Promise.all([fetchOverview, fetchSummary, fetchSectors])` |
| 切换模块 | 惰性加载：首次进入该模块时请求 | 涨跌复盘/选股追踪首次进入才请求 |
| 自动刷新 | 仅大盘概览模块 active 时每 60s 刷新 | 其他模块不自动刷新 |
| 日期切换 | 重新请求对应日期的数据 | 涨跌复盘/选股追踪的日期选择 |
| 错误处理 | API 失败显示错误提示，不阻塞页面 | 每个 API 独立 try/catch |

### 4.4 涨跌复盘分页+排序

**分页**：前端本地分页（数据全量拉取后前端切割），可选每页 10/20/50/100 条。

**排序**：点击表头触发本地排序：
- 点击一次：升序
- 再点击：降序
- 第三次点击：恢复默认（按数据源顺序）
- 排序指示器：表头显示 ▲/▼ 箭头

```javascript
function sortTable(data, field, order) {
  return [...data].sort((a, b) => {
    const va = parseFloat(a[field]) || 0;
    const vb = parseFloat(b[field]) || 0;
    return order === 'asc' ? va - vb : vb - va;
  });
}

function paginate(data, page, pageSize) {
  const start = (page - 1) * pageSize;
  return data.slice(start, start + pageSize);
}
```

### 4.5 选股追踪数据流

```
选择日期 + 维度
    ↓
GET /api/picks?date=YYYYMMDD&tag=all|limitup|range
    ↓
渲染候选股票列表（含各维度分）
    ↓
每只股票后面显示后续5个交易日K线涨跌幅
    ↓
tracking[0] = 次日, tracking[1] = 次次日, ...
```

## 5. 需新增后端模块

### 5.1 `GET /api/picks` — 选股追踪接口

该接口需要：
1. 从 `daily_picks` 表按 `trade_date` 和 `data_tag` 筛选
2. 从 `stock_daily` 表取后续5个交易日的 `change_pct`
3. 返回格式化数据

**现有表结构**：
```sql
daily_picks: id, code, name, trade_date, total_score, data_tag, 
             score_chip, score_money, score_sector, score_trend, 
             score_market, score_position, is_pick, `rank`

stock_daily: code, trade_date, change_pct, close, ...
```

**实现位置**：`web_server.py` 新增 `api_picks()` 方法

### 5.2 日期列表

`daily_picks` 表 `SELECT DISTINCT trade_date ORDER BY DESC`

## 7. 风险与备选

| 风险 | 影响 | 应对 |
|------|------|------|
| 选股历史日期数据量过大 | 接口响应慢 | 前端做分页，限制返回50条/次 |
| 后续5日涨跌幅可能有null | 展示空白 | 前端显示"--"，不影响排序 |
| 涨跌复盘数据量大（日涨停>100只） | 全量拉取慢 | 改为后端分页（可选，第一版先前端分页） |
| 原型HTML在127.0.0.1:8899不能直接打开端口 | 需要额外http服务 | 有两种方案提供静态文件 |

### 7.1 静态文件服务方案

**方案A（推荐）**：web_server.py 增加 `/` 路由直接返回 index.html
- 用户直接访问 `http://localhost:8899/` 即可
- 现有根路由已返回简单首页，改为内联完整前端HTML
- 同源，无跨域问题

**方案B**：`nohup python3 -m http.server 8900 --directory docs/design/`
- 原型 `web_prototype.html` 通过 8900 端口访问
- mock 数据，独立于后端
- 用于产品评审阶段

最终上线走方案A，方案B仅用于原型评审。
