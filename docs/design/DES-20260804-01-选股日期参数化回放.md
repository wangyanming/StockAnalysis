## 0. 摘要（TL;DR）

让 dev 环境的 V2 选股支持「指定交易日回放」，核心是把散落在 **`core/analyzer/scorer.py`** 内部的 8 处 `datetime.now()` 锚定 + 大盘缓存 + `score_candidate` 签名，从「只看今天」改为「可指定交易日」。回放入口用已有的 **`daily_pick_v2_backtest.py`**（已是有参 `pick_stocks_v2(trade_date=None)`，仅比生产少了 `_save_picks_to_db`），通过新增模块级锚定 `set_trade_date()` 统一口径。

**不改生产** `daily_pick_v2.py` 的行为（默认跑当天不变），但**方案本身也作用于生产**——通过「参数直传 + 默认 None→当天」的兼容式设计，生产 `pick_stocks_v2()` 保持零参调用不变，从而把改动风险收敛在 dev。

落地后跑 `backtest/dev_replay_jul.py` 回放 7 月交易日，逐日重算 dev 分数，写 `dev_replay_jul` 表，与 `daily_picks` 按 `trade_date+code` 对比候选集合与各维度分数。

## 1. 改造目标与范围

### 1.1 目标

1. 让 `pick_stocks_v2(trade_date)` 能被指定任意交易日全链路回放（涨停→连板→板块→候选池→评分），**分母全用回放日**。
2. 生产默认行为不变：不传参时仍「跑当天」。
3. 验收验证：**候选集合一致率 + total/各维度一致率**（对比 `daily_picks` 落库）。

### 1.2 范围清单

| 文件 | 改动性质 | 改动点 |
|------|---------|--------|
| `core/analyzer/daily_pick_v2_backtest.py` | 回放入口（**主线改造**） | 已是有参；补传 `trade_date` 进 scorer/涨停模块，删除残留 1 处 `datetime.now()` 兜底歧义 |
| `core/analyzer/scorer.py` | **核心改造**（独立文件） | 新增模块级锚定 + 8 处 `datetime.now()` 改读锚定 + `_market_cache` 交易日重置 + `score_candidate`/`check_market_status` 签名 |
| `core/analyzer/daily_pick_v2.py` | **生产入口（仅兼容微调，不动默认行为）** | `pick_stocks_v2(trade_date=None)` 增加可选参数 + 兜底 `_save_picks_to_db` 沿用「当天」语义（见 §1.3 决策） |
| `core/fetcher/limit_up_analysis.py`（zt.*） | 涨停/连板模块 | `get_today_limit_up` 已支持 `trade_date` 参数（无需改）；`get_continuous_trackers` **无日期过滤**，需新增 `trade_date` 参数（见 §4） |
| `backtest/dev_replay_jul.py` | 驱动脚本（已存在，微调） | 补打对比统计口径 + date 数组从 DB 查 DISTINCT 交易日（见 §7） |

### 1.3 生产 `daily_pick_v2.py` 是否也改？（决策）

**要改，但只做「兼容式微调」，不动生产默认行为。**

- **原因**：`scorer.py` 是独立文件，生产也 `import` 同一个 `scorer.py`。若只给 backtest 的 scorer 加锚定、生产不加，会出现「同一份 scorer 代码，dev 回放能指定日期、生产却写死当天」的分叉，后续维护会双份漂移。
- **做法**：`scorer.py` 的锚定默认值 = `None → datetime.now()`，即不带 `set_trade_date()` 时行为与现在**完全一致**。生产 `main.py` / `close_task.py` 调用 `pick_stocks_v2()`（零参）时，锚定为当天，等价现状。
- **风险**：生产 scorer 行为零变化，因此改动是「默认低风险」的注入式，非行为改写。生产侧不主动调用 `set_trade_date()`，保障存量 cron 不变。

> ⚠️ 明确边界：**方案核心落点在 dev 的回放入口（backtest）+ 共享的 scorer.py**；生产 `daily_pick_v2.py` 仅加签名、不改逻辑，且**不在生产跑回放**。

## 2. 参数化设计

### 2.1 `pick_stocks_v2(trade_date=None)` 默认值策略

```python
def pick_stocks_v2(trade_date: str = None):
    # 回放优先：显式交易日
    # 默认回退：当前日期（保持生产"跑当天"行为不变）
    today_str = trade_date or datetime.now().strftime('%Y%m%d')
    today_dash = f"{today_str[:4]}-{today_str[4:6]}-{today_str[6:8]}"

    # 关键：把交易日锚定贯穿到共享 scorer 模块
    set_trade_date(today_str)   # scorer 模块级锚定（见 §3）
```

- backtest 版已有 `trade_date` 参数与 `today_str/today_dash` 推导（已验证），**无需新造**。
- 必须在 `pick_stocks_v2` 开头调用 `set_trade_date(today_str)`，因为后续 `check_market_status()` / `score_candidate()` 内部都要读这个锚定。

### 2.2 日期格式统一

| 用途 | 格式 | 现状 |
|------|------|------|
| 表主键/过滤（`stock_daily.trade_date`、`daily_limit_up.trade_date`、`daily_picks.trade_date`） | `%Y%m%d` 紧凑（`20260731`） | 现状已统一为紧凑 |
| 日报/板块 `sector_performance.record_date`、`index_quotes.record_date` | `%Y-%m-%d` 连字符（`2026-07-31`） | 现状已统一为连字符 |

**约定**：内部统一维护 `_today_str`（紧凑）与 `_today_dash`（连字符）两个派生值，由锚定函数一次性生成，杜绝各函数自己 `strftime`。backtest 已这么做了，scorer 改造沿用同一约定。

### 2.3 模块级变量 vs 函数参数直传（取舍建议）

| 方案 | 优点 | 缺点 |
|------|------|------|
| **模块级锚定 `set_trade_date`（推荐）** | 最小改动；`score_candidate(code,name)`/`check_market_status()`/各维度函数签名全都不用改；一处重置大盘缓存；生产默认不变 | 模块级全局态，需保证每次 `pick_stocks_v2` 必先 `set_trade_date`；并发/多进程需各自设置（回放是单进程串行，无冲突） |
| 函数参数直传 `score_candidate(code,name,trade_date)` | 无全局态、可重入性好 | 侵入大：`score_candidate`→各维度函数→`check_market_status` 全链路每个函数都要加参数，8+ 处签名全改，改动面成倍，且 scorer 是独立文件调用链复杂 |

**推荐：模块级锚定 `set_trade_date(trade_date_str)`**。理由：
1. **最小改动**：只需在 scorer.py 顶部加锚定 getter/setter，8 处 `datetime.now().strftime()` 改为读 `_today_str`（或新增 `_get_today()`），签名全部不动。
2. **大盘缓存重置**：`_market_cache` 必须随交易日重置，模块级锚定天然能在 `set_trade_date` 时把 `_market_cache` 清空，一处解决（见 §6）。
3. **可回放性**：回放驱动单进程串行逐日调用，每天先 `set_trade_date` 再 `pick_stocks_v2`，状态完全可控。
4. 与生产试验副本 `scorer_v6_copy.py` 已有 `set_trade_date + _today_str/_today_dash` 模式保持一致，参考成熟实现。

> ⚠️ `scorer_v6_copy.py` 是生产试验副本，**dev git 库里没有**。方案明确：dev 复用「模块级变量」这一模式（参考其实现在 scorer.py 内实现），不 copy 该文件。

## 3. `score_candidate` 及 8 处 `datetime.now()` 具体改法

### 3.1 推荐方案：模块级锚定 getter/setter

在 `core/analyzer/scorer.py` 顶部（第 69 行 `_market_cache` 附近）新增：

```python
# ── 交易日锚定（回放用）──────────────────────────
_today_str = None   # 紧凑格式 %Y%m%d
_today_dash = None  # 连字符格式 %Y-%m-%d

def set_trade_date(trade_date_str: str):
    """设置回放交易日锚定。trade_date_str 为 %Y%m%d 紧凑格式。
    同时重置大盘缓存，防止跨交易日串数据。"""
    global _today_str, _today_dash, _market_cache
    _today_str = trade_date_str
    _today_dash = f"{trade_date_str[:4]}-{trade_date_str[4:6]}-{trade_date_str[6:8]}"
    _market_cache = {'time': 0, 'data': None}   # 缓存随交易日重置（§6）

def _get_today() -> str:
    """取当前锚定交易日（紧凑）；未设置时回退 datetime.now()，保持生产默认跑当天。"""
    return _today_str or datetime.now().strftime('%Y%m%d')

def _get_today_dash() -> str:
    """取当前锚定交易日（连字符）。"""
    return _today_dash or datetime.now().strftime('%Y-%m-%d')
```

## 4. 涨停/连板模块无日期过滤的处理

### 4.1 `get_today_limit_up(trade_date=None)` —— 已支持，无需改

```python
def get_today_limit_up(self, trade_date: str = None):
    if not trade_date:
        trade_date = datetime.now().strftime("%Y%m%d")
    return db.fetchall("SELECT * FROM daily_limit_up WHERE trade_date=%s ...", (trade_date,))
```
其内部已按 `daily_limit_up.trade_date = T日` 过滤，backtest 已传 `trade_date=today_str`。✅ 无需改，但确认生产 `daily_pick_v2.py` 第 57 行调用 `get_today_limit_up()` 时不传参（保住默认当天）。

### 4.2 `get_continuous_trackers(min_days=2)` —— 无日期过滤（必须改）

**问题核实**：连板取自 `limit_up_tracking` 表，该表是「**最新状态快照**」——表结构带 `UNIQUE(code)`，只存每只股**最近一次**的 `latest_limit_date / total_limit_days / current_board_count`，**不保存逐日历史**（`update_tracking` 是对现有行做 UPDATE，非插入新历史行）。因此**无法按 T 日回溯查询历史连板状态**。

```python
# 现状（无日期过滤，总是查最新快照）
def get_continuous_trackers(self, min_days: int = 2):
    rows = db.fetchall(
        "SELECT * FROM limit_up_tracking WHERE total_limit_days >= %s "
        "ORDER BY total_limit_days DESC, max_board_count DESC", (min_days,))
    return rows
```

**处理决策**：
- 若回放目标只是「对照分数层面」差异，且连板只影响 `trackers` 结果展示（不入候选/评分主链路），可**保留无日期行为**，在方案中标注「回放日连板为最新快照，非历史口径」为已知边界。
- 若要真正支持历史连板回放，需引入**连板历史快照表**或按 `daily_limit_up` 聚合重现连板——**成本高、超出本次范围**，建议列入后续迭代。

**本次方案结论**：`get_continuous_trackers` **不新增日期参数**，明确其为「最新状态快照」，判定为回放的**已知不可回放项**（见 §8 风险边界），不阻塞主链路对比。

### 4.3 生产 `get_today_limit_up`/`get_continuous_trackers` 调用点

- `daily_pick_v2_backtest.py:57` `get_today_limit_up(trade_date=today_str)` ✅ 已传参
- `daily_pick_v2_backtest.py:83` `get_continuous_trackers(min_days=1)` —— 快照语义，保留

## 5. 90 天窗口 `three_months_ago` 的回放正确化

**问题**：生产 `daily_pick_v2.py` 第 130 行 `three_months_ago = (datetime.now() - timedelta(days=90))`，用于 EXISTS 子查询判定「近 3 月内是否曾涨停」。若回放早期（如 7/1）时用真实 now 算窗口，会把「8 月才涨停」的股票算进 7/1 的候选资格，**口径偏移**。

**结论**：backtest 已正确 —— 第 139 行：
```python
three_months_ago = (datetime.strptime(today_str, '%Y%m%d') - timedelta(days=90)).strftime('%Y%m%d')
```
即在回放日基础上向前推 90 天，而非 datetime.now()。**已验证，无需再次改。** 需在代码评审中确保 `daily_pick_v2_backtest.py` 的这条未被动回退。

配套滑动窗（近5日首板 `_five_days_ago`、六十日K线 `_sixty_days_ago`、近5日换手）backtest 均已基于 `today_str` 回推（202-206 行区域），一并确认即可。

## 6. 大盘缓存 `_market_cache` 跨交易日重置

**现状**（scorer.py 149-185）：
```python
_market_cache = {'time': 0, 'data': None}
def check_market_status():
    global _market_cache
    now = time.time()
    if now - _market_cache['time'] < 900 and _market_cache['data']:
        return _market_cache['data']   # 15分钟内命中缓存
    ...
    _market_cache = {'time': now, 'data': result}
```

**风险**：缓存键是**时间**（15 分钟），不含交易日。回放时若同一天内连续回放多个交易日（如 7/1、7/2 都在几分钟内跑完），第 2 天会因「距上次 <900s」命中第 1 天的缓存 —— **跨日串数据**。

**改法**：缓存键改为 **（交易日 + 时间）双条件**，并把重置逻辑挂在 `set_trade_date`：

```python
def check_market_status():
    global _market_cache
    today = _get_today_dash()
    now = time.time()
    # 缓存命中条件：同一天 + 15分钟内
    if (_market_cache['date'] == today
            and now - _market_cache['time'] < 900
            and _market_cache['data']):
        return _market_cache['data']
    ...
    # 写入时记录交易日
    _market_cache = {'date': today, 'time': now, 'data': result}
```

并在 `set_trade_date()` 内强制 `_market_cache = {'date': None, 'time': 0, 'data': None}`（§3.1 已含），双保险杜绝跨日串。

## 8. 风险与边界

### 8.1 明确「改后仍无法回放」的项

| # | 项 | 原因 | 处置 |
|---|----|------|------|
| R1 | **连板 `get_continuous_trackers`** | `limit_up_tracking` 为最新状态快照（`UNIQUE(code)`，无逐日历史） | 保留现状，标注「快照语义」，不阻塞主链路；列为后续迭代引入历史快照表 |
| R2 | **`fetch_sina_quote` / 新浪实时 API 回落** | `score_candidate` 里 `_get_today_quote_from_db` 取不到时会调 `fetch_sina_quote` 实时接口 → 回放日拿不到历史实时价 | 关闭回落 or 保证 dev 有回放日 `stock_daily`；若 q 为空则该维度走 DB，需评审是否影响一致率 |
| R3 | **`_save_picks_to_db` 落库日期**（仅生产 `daily_pick_v2.py`） | 写 `daily_picks.trade_date` 用 `datetime.now()` | 回放**不落生产** `daily_picks`（backtest 已无此调用）；`dev_replay_jul` 是 dev 独立对照表，不污染生产 |
| R4 | **`build_candidate_pool` 未被 backtest 主链路调用** | backtest 用 `raw_candidates`/内部扫描构建候选，未走 `build_candidate_pool` | 需确认回放候选口径与生产 `daily_picks` 候选口径一致，否则候选集合对账失真（见 §8.2） |

### 8.2 候选集合口径一致性（关键校验点）

生产 `daily_pick_v2.py` 与 backtest 在构建候选池时路径**结构相同但可能细节有差**（生产全市场扫描 + 涨停热点；backtest 同）。**候选集合一致率必须以同一口径对账**：建议对比「`daily_picks.is_pick=1`（生产精选）vs dev 回放 `source` 为涨停热点/强势涨幅的集合」，并先跑**一个单日**抽查 `daily_picks.is_pick=1` 与 dev 落库交并集，锁定口径后再全月回放。

### 8.3 验收标准

1. **生产默认跑当天行为不变**：不传参 `pick_stocks_v2()` 输出与改造前一致（跑一天对比总分/候选）。
2. **同一股跨日期分数不同**：取任意 3 只股票，回放 7/1 与 7/3，`total_score` 与各维度分应随 `trade_date` 变化（验证锚定真正生效，而非都被 now 拉平）。
3. **单日候选数与 daily_picks 一致**：任一交易日（如 20260715），dev 回放候选集合与 `daily_picks` 该日 code 集合达到既定一致率阈值（建议 ≥95% 候选一致，分数字段一致率 ≥90% 或偏差均值 < 设定容忍）。
4. 大盘缓存：连续回放 7/1→7/2（间隔 <15 分钟），7/2 的 `market.sh_change` ≠ 7/1（验证缓存按交易日重置）。

### 8.4 其他风险

- **并发/多进程**：模块级锚定是全局态，若 cron 与回放并发跑会互相覆盖 `_today_str`。**约束**：回放期间不调度生产 cron；或回放开独立进程（生产 `main.py` 与回放脚本不共用进程内状态，天然隔离）。
- **`record_date` vs `trade_date` 命名差异**：板块/index_quotes 用 `record_date` 连字符、其余用 `trade_date` 紧凑 —— 改法必须分别用 `_today_dash`/`_today_str`，不可混用。
