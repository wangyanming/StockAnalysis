## 一、背景与问题

当前选股逻辑在代码里硬取"今天"（`datetime.now()`），无法重跑历史日期的选股，回测因此失真（历史日选股拿的是实时价/实时大盘）。需求：把选股改为可按历史日期（trade_date）重跑，支撑回测。

**重要基线说明**：08-04 曾审定 DES-20260804-01，但 dev 分支经改造1（limit_up 清理）+ 改造2/3（DB 连接本地化）+ 生产已切 dev 部署后，代码基线已变，本方案按**当前 dev 基线**重新校准，与旧方案差异见第六节。

## 二、改造范围（精确到文件/函数/行）

### 1. `core/analyzer/daily_pick_v2.py`（生产入口，加参 + 透传锚定）

**核心改动：`pick_stocks_v2` 增加可选参数，默认 None 保持"取今天"现有行为。**

```python
# L33 签名改造
def pick_stocks_v2(trade_date: str = None):
    """trade_date=None 时保持现有取今天行为；传入 %Y%m%d 时用该日锚定全部取数。"""
    t = trade_date or datetime.now().strftime('%Y%m%d')   # 统一锚定变量，下称 t
    t_dash = f"{t[:4]}-{t[4:6]}-{t[6:8]}"                  # 连字符派生（板块/指数用）
```

**默认 None → 取今天的具体实现**：函数开头以 `t = trade_date or datetime.now().strftime('%Y%m%d')` 一次性派生锚定变量，后续所有取数改用 `t` / `t_dash`。传 None 时 `t` == 今天的紧凑串、`t_dash` == 今天的连字符串，行为与现状完全一致；传历史日期时，整个函数按该日取数。**这是"保持取今天"的落地实现：不是保留散落的 `datetime.now()`，而是统一收敛到一个可由 trade_date 覆盖的锚定变量。**

**函数内各取数点逐一改为用锚定变量（改动点与现状对照，行号为缓存清理后实测）：**

| 行 | 现状 | 改为 |
|----|------|------|
| L40 | `zt = LimitUpAnalyzer()` | `zt = LimitUpAnalyzer()`（**构造器无日期参数，不改**，见 §3） |
| L57 | `today_up = zt.get_today_limit_up()` | `today_up = zt.get_today_limit_up(trade_date=t)`（get_today_limit_up 已支持历史，见 §3） |
| L103 | `today_str = datetime.now().strftime('%Y%m%d')` | `today_str = t`（直接用锚定变量） |
| L104-105 | `target_date = today_str if check and ... else MAX(trade_date)` | 逻辑保留；`check` 查询改用 `(t,)` 判该日 stock_daily 是否有数据（回测日数据已就绪则命中） |
| L119 | `three_months_ago = (datetime.now() - timedelta(days=90)).strftime('%Y%m%d')` | `three_months_ago = (datetime.strptime(t, '%Y%m%d') - timedelta(days=90)).strftime('%Y%m%d')`（**90天窗口必须以回放日回推，非 now**） |

**不在回放取数范围的副作用（防实施误改，分类处理）**：
- L470 `format_v2_report` 的 `now = datetime.now()`：仅报告标题日期，纯展示（同 scorer 标题 L938，不改）
- L639 `_save_picks_to_db` 的 `today = datetime.now()`：写库副作用，**本次必改**（与取数一致）——写库 trade_date 改为锚定变量 `t`（回放日），因`_save_picks_to_db` 写 `daily_picks.trade_date = 今天(now)` 会污染回放数据归属（§5 写库日期锚定）
- L745 `daily_top5.json` 的 `'date': datetime.now()`：写 JSON 文件副作用，非 DB trade_date，**不改**（与 L639 写库是两回事，勿混淆）——此处「不改」指**生产逻辑** L745 代码行不在回放取数范围、生产仍照常写当日 JSON；**回放路径则整段跳过 JSON 落盘**（含 daily_picks.json / daily_picks_v2.json），两条意思不冲突：用 `trade_date` 是否为 None 判断，None（生产）照常写 JSON、非 None（回放）跳过（详见 §5 回放写库日期锚定）

> 约束：`t`（`%Y%m%d` 紧凑）与 `t_dash`（`%Y-%m-%d` 连字符）必须在函数开头一次派生、全函数复用，不得在内部各自 `strftime`，杜绝日期格式混用。

### 2. `core/analyzer/scorer.py`（真正按日期查数据的核心）

**推荐：模块级日期锚点（set_trade_date）而非逐函数传参**，理由：8 处取数散落在不同评分函数、且 `score_candidate`→各维度函数调用链深，逐函数加参侵入大、易漏。

**新增模块级锚点（scorer.py 顶部）：**

```python
def set_trade_date(trade_date_str: str):
    """设置回放交易日锚定（%Y%m%d）。未设置时取数回退 datetime.now()，即生产默认当天。
    仅做日期锚定（模块缓存 _market_cache 已删除，见下），聚焦于锚定变量本身。"""
    global _anchor_date, _anchor_date_dash
    _anchor_date = trade_date_str
    _anchor_date_dash = f"{trade_date_str[:4]}-{trade_date_str[4:6]}-{trade_date_str[6:8]}"

def _get_today():        # 紧凑 %Y%m%d；未设置回退 datetime.now()
    return _anchor_date or datetime.now().strftime('%Y%m%d')

def _get_today_dash():   # 连字符 %Y-%m-%d；未设置回退 datetime.now()
    return _anchor_date_dash or datetime.now().strftime('%Y-%m-%d')
```

**8 处 `datetime.now()` 逐一改读锚点（现状行号 → 改法，行号为缓存清理后实测）：**

| L153 | `check_market_status` | `today_dash = datetime.now().strftime('%Y-%m-%d')` | `today_dash = _get_today_dash()` |
| L201 | `score_chip_structure` | `today = datetime.now().strftime('%Y%m%d')` | `today = _get_today()` |
| L298 | `score_momentum` | `today = datetime.now().strftime('%Y%m%d')` | `today = _get_today()` |

**签名与缓存细节：**
- `score_candidate(code, name, market=None)`（L839）→ **签名已是 `(code, name, market=None)` 且本方案不动它**：`market` 是"大盘结果旁路传入"优化参数（daily_pick_v2 L188 传入，避免逐只查库），**与日期锚点正交、方案不改**；日期改造仅在函数内各维度取数处改用模块锚点 `_get_today()`/`_get_today_dash()`（签名不变，靠锚点取日）。
- `check_market_status()`（L146，内部 `today_dash` 在 L153）→ 内部改读 `_get_today_dash()` 取锚定日期指数；**签名可不加参**（靠锚点）。因 `market=None` 兜底路径（score_candidate L866 `if market is None: market = check_market_status()`）也从本函数取大盘，锚点须让 `check_market_status` 内部也读锚定日期，确保回放时 daily_pick_v2 L47 与 score_candidate 兜底两条路都取回放日大盘。
- `_market_cache` 已在 commit 1a9f291 删除（大盘查询上移 daily_pick_v2 单次调用），`check_market_status()` 为纯查询、无跨调用隐藏状态，**回放不再有跨日串台问题，本方案无需处理缓存**。
- **第 9 处取数点（SQL 内置 CURDATE 通道）**：L810 `CURDATE()` SQL（20日窗口），位于 `build_candidate_pool` 的 SQL：`SELECT MIN(low) as min_l, MAX(high) as max_h FROM stock_daily WHERE code=%s AND trade_date >= DATE_FORMAT(DATE_SUB(CURDATE(), INTERVAL 20 DAY), '%%Y%%m%%d')`。与上表 8 处 python `datetime.now()` 不同，这是**在 SQL 内置 CURDATE 的取数通道**，同样需锚定 → 改为参数化：`trade_date >= %s` 传 `_get_today()` 回推 20 日的串（注意现有 `%%Y%%m%%d` 是给 mysql 的格式串，改后直接用 python 算好的串绑定，不再用 CURDATE）。

**默认 None 行为不变的兜底**：未调 `set_trade_date()` 时 `_anchor_date=None`，`_get_today()`/`_get_today_dash()` 返回 `datetime.now()`，各评分取数 == 现状。生产 `main.py`/`close_task.py`/cron 调 `pick_stocks_v2()` 不传参时，`daily_pick_v2` 也不调 `set_trade_date`，锚点保持 None → 全程等价今天。

历史 `trade_date` 依赖下列表该日期是否有数据。**已核验：7/1~7/31 共 23 个交易日，`stock_daily` / `daily_limit_up` / `index_quotes` / `sector_performance` 均有数据 → 7月整月回放可行。**

| 数据源 | 表/来源 | 7月可用性 | 备注 |
|--------|---------|-----------|------|
| 个股日线 | stock_daily | ✅ 23交易日 | 评分/技术指标基础 |
| 涨停池 | daily_limit_up | ✅ 23交易日 | 候选池来源 |

## 五、回测消费方式

- 回测脚本：枚举交易日列表 → `for td in trade_days: pick_stocks_v2(trade_date=td)` → 收集结果
- **回放大盘锚定**：`pick_stocks_v2` 内部 L47 `market = check_market_status()` 依赖日期锚点取回放日大盘（与缓存清理后一致）；因此调用 `pick_stocks_v2(trade_date=td)` 前需先 `scorer.set_trade_date(td)`，使 `check_market_status` 内部也读回放日指数，同时 score_candidate 兜底路径（L866）同样取回放日大盘。
- **锚点全局残留复位**：`_anchor_date` 是 scorer.py **模块级全局**。若**同一进程**先回测（`set_trade_date(td)`）后生产（`pick_stocks_v2()` 不传参），会串锚点导致生产错取回测日数据。规避：
  - 回测应在**独立进程**跑（推荐）；或
  - 回测完必须 `set_trade_date(None)` 复位锚点，再调生产逻辑
  - `pick_stocks_v2()` 不传参时内部 `t = datetime.now()` 是今天的，但 scorer 锚点若非 None 会覆盖评分取数 → 两者必须一致
- **写库日期锚定**：`pick_stocks_v2(trade_date=td)` 时选股结果应写入 `daily_picks.trade_date = td`（回放日），而非 `datetime.now()`。`_save_picks_to_db` 的写库 trade_date 必须改用 `pick_stocks_v2` 派生的锚定变量 `t`（回放时=回放日、默认 None=今天），统一取数/写库日期来源一致。这样回放数据归档到回放日，不污染今天窗口，且与生产每天写今天一致（生产无参→t=今天→写今天，天然不受影响）
- **回放不写 JSON 文件（三 JSON 无消费方）**：已全局核实 `daily_top5.json` / `daily_picks.json` / `daily_picks_v2.json` **均无消费方**（web_server 直接查 `daily_picks` DB 表，不读 JSON；定时任务也不读；三个 JSON 均在 .gitignore、纯本地冗余）。因此**回放路径不写这三个 JSON 文件**，避免回放覆盖生产今天文件；**生产照常写**。实现提示：在 `pick_stocks_v2` 内用 `trade_date` 是否为 None 判断——None（生产）时照常写 JSON，非 None（回放）时跳过 JSON 落盘（仍写 daily_picks DB 表回放日）。这与 L745 的关系：L745 `daily_top5.json` 的 date 写今日属于**生产副作用、不改**（在回放取数范围外、生产仍写）；**整段 JSON 落盘是否执行由 `trade_date` 判断控制**，回放非 None 即跳过，两层意思已理顺不冲突
- 参考旧 backtest_v6copy 做法，但以新签名为准（`daily_pick_v2_backtest.py` 为保留的历史副本（untracked，含 `pick_stocks_v2(trade_date=)` 有参入口），**本次以正式 `daily_pick_v2.py` 的 `pick_stocks_v2(trade_date=)` 为准，不依赖该副本**）
- **替代方案（备选）**：`backtest/time_machine.py` 仍存在（patch datetime 模块级），但**不推荐**——patch 全局 datetime 易漏模块导致假回测（07-31 已栽过），显式传 trade_date 更稳
