### 根因：评分模型机制性偏好涨停票

**人气辨识度(25分)** 与 **主线属性(25分)** 合计50分，涨停票在此两项天然独占高分：

| 子维度 | 满分 | 涨停票得分 | 非涨停票得分 | 差距 |
|--------|:----:|:----------:|:------------:|:----:|
| 涨停辨识度(12) | 12 | 12（今日已涨停） | 4（近5日1次涨停） | **8分** |
| 板块龙头性(8) | 8 | 8（龙一） | 2（非涨停，跟风） | **6分** |
| 股性活跃度(5) | 5 | 5（封板振幅大） | 3 | 2分 |
| 主线锚定(15) | 15 | 15（涨停板块=主线） | 15或0 | 0~15分 |
| 板块地位(10) | 10 | 10（当天涨停的龙一） | 2（非涨停） | **8分** |
| **小计** | **50** | **50** | **~26** | **~24分** |

量价结构的30分不足以抹平24分的固有差距。即使非涨停票量价全满(30分)，涨停票量价得一半(15分)，总分仍高19分。

### 核心矛盾：选股系统的买入时点错位

```
v6选股日(T日) → 选出涨停票 → T+1开盘买入 → T+2卖出
```

A股T+1制度下，T+1开盘追入涨停票的次日接力，从统计上看是低胜率策略：

- T+1高开3-7%买入→当天浮亏（冲高回落/炸板）
- T+2低开→被迫止损
- 只有少数龙头能走连板行情，但龙头在首板时极难识别

**选股系统要解决的是"买什么"，而不是"买了第二天涨停的是什么"——去买已经涨停的，就变成了追涨。**

## 修正目标

### 新的规则约束（硬性，不可违反）

1. **禁止推当天涨停/大涨(≥9%)的票** —— T+1接力是低胜率
2. **涨停票只能作为"观察池"参考，不能是"买入池"推荐**
3. **评分模型必须区分T日状态**：T日大涨→扣分，T日回调/启动/缩量整理→加分
4. **选股系统必须接受A股T+1的现实约束**：买在回调日或启动日，不是涨停日

### 选股方向

综合 `REQ-20260611-02-根因分析与方向重审.md` 的建议，选定 **两种选股类型**：

| 类型 | 选股日特征 | 买入逻辑 | 标的特征 |
|:----|:----------|:---------|:---------|
| **A. 首板缩量回踩** | T-1或T-2涨停，T日缩量回调 | T+1竞价低吸 | 有辨识度、回调不破位、缩量惜售 |
| **B. 低位放量启动** | T日涨幅3~7%（非涨停），放量突破 | T+1竞价参与 | 均线刚拐头、突破20日线、板块配合 |

**为什么不做"纯低位潜伏"和"事件驱动"：**
- 纯低位潜伏没有启动信号，可能永远不涨
- 事件驱动依赖外部数据源（晚间消息），不在当前5大维度框架内，且时效性不可控
- 首板回踩+低位启动是A股短线最成熟的两种模式

## 模块详细设计

### 0️⃣ 核心修正：T日状态扣分机制（评分模型级别）

**这是最核心的变化**——以往评分模型对T日涨停/大涨无惩罚，甚至奖励（涨停辨识度给满分）。

新规则：评分前先做T日状态评估，产生一个**修正系数**，作用于最终总分：

```
T日状态修正（-20 ~ +10分）：
  - 涨停(≥9.5%)     → -20（最高扣减，禁止涨停票进入精选）
  - 大涨(7~9.5%)    → -10（大涨后T+1高开难接力）
  - 涨幅5~7%        → -5（中阳上影多，需消化）
  - 涨幅2~5%        → +3（温和放量启动，理想买入区间）
  - 涨幅0~2%        → +5（平盘启动，最佳状态窗口）
  - 跌幅0~-3%且缩量  → +10（缩量回调洗盘，最佳买点）
  - 跌幅0~-3%且放量  → 0（放量阴跌，观望）
  - 跌幅-3~-7%      → -3（跌幅过大，趋势破坏）
  - 跌幅< -7%       → -10（大跌，不参与）
```

**该修正在所有策略中统一执行，不因策略不同而改变。**

这是在总分维度上做最终修正，不干涉各个子维度的独立评分逻辑。

### 1️⃣ 市场主线识别模块（F1_市场主线识别.py）

**与v6保持一致**，不做修改。

```
输入：daily_limit_up(当日涨停行业分布)、sector_performance(板块涨跌幅)
逻辑：涨停数×0.4 + 涨幅×0.3 + 最高板×0.3 综合评分
模式判定：strong_trend / pullback / rotation
```

### 2️⃣ 基础辨识度评分（score_base_renqi.py，25分）← 修正版

**修正重点**：从"加分涨停辨识度"改为"加分近期辨识度"，且与T日是否涨停脱钩。

**对比v6的变化**：

| 子维度 | v6逻辑 | v7逻辑 | 变化 |
|--------|--------|--------|:----:|
| 涨停辨识度(12) | 近5日涨停次数 | 近10日涨停次数（连板历史更说明问题） | 周期拉长 |
| 板块龙头性(8) | 当日板块封板排位（涨停票锁定满分） | **近3日**板块封板排位（只要有连板历史的都可计入） | 不局限于T日涨停 |
| 股性活跃度(5) | 同v6 | 同v6 | 不变 |

**详细逻辑：**

| 子维度 | 满分 | 逻辑 |
|--------|:----:|------|
| 涨停辨识度 | 12分 | 近10日涨停次数：4次→+12, 3次→+10, 2次→+7, 1次→+4, 0次→0 |
| 板块龙头性 | 8分 | 近3日内是否板块龙一/前排：龙一+8, 前排+5, 跟风+2, 无→0 |
| 股性活跃度 | 5分 | 近10日均振幅>5%→+5, >3%→+3, ≤3%→0 |

**关键变化**：涨停辨识度只看"近期涨停历史"，不看"今天是否涨停"。非涨停票如果近10日有2~3次涨停，同样能拿高分。

### 3️⃣ 基础主线评分（score_base_zhuxian.py，25分）← 修正版

**修正重点**：在主线锚定中已自动覆盖到主线板块票，板块地位判定不再依赖T日是否涨停。

**逻辑（同v6）：**

| 子维度 | 满分 | 逻辑 |
|--------|:----:|------|
| 主线锚定 | 15分 | 个股所在板块在主线TOP3内→+15, TOP5内→+10, TOP10→+5, 非主线→0 |
| 板块地位 | 10分 | 板块龙头（近3日有连板/最先封板）→+10, 前排→+6, 后排→+2, 非主线→0 |

**关键变化**：板块地位判定不再看"今天是否涨停"，而是看"近3日板块内地位"。一个票是板块龙头，即使今天没涨停（在回调），它依然是这个板块的龙头。

### 4️⃣ 状态+量价评分（score_state_liangjia.py，30分）← 重写

**最重要的是增加的T日状态评分**：融合了原来的分歧一致判断+趋势强度+量能健康度+新增的T日状态评分。

| 子维度 | 满分 | 说明 |
|--------|:----:|------|
| T日状态评分 | 12分 | 根据T日涨跌幅+量价配合判断买入时机（新增） |
| 技术结构评分 | 12分 | 均线排列+位置评估+支撑位（重写，不再奖励涨停） |
| 量能健康度 | 6分 | 量比+筹码换手（精简） |

#### T日状态评分（12分）——新增

这是v7的核心创新。不再用"分歧一致"的模糊概念，而是直接用T日涨跌+量价配合判断买入时机：

| T日状态 | 得分 | 说明 |
|---------|:----:|------|
| **缩量回调(跌幅0~-4%)，量比<0.8，价格在MA10/MA20之上** | +12 | **最佳：洗盘衰减，支撑有效** |
| **温和放量启动(涨幅2~7%，非涨停)，量比1.5~3** | +10 | **最佳：放量启动，趋势开启** |
| **平盘小幅震荡(涨幅0~2%或跌幅0~-2%)，量比0.8~1.5** | +8 | **横盘整理，变盘前夜** |
| **缩量回调(跌幅0~-4%)，量比0.8~1.5，价格在MA10/MA20之上** | +8 | **缩量回调但量不够极致** |
| **放量突破涨停(≥9.5%)** | -12 | **涨停票不推荐，严重扣分** |
| **放量中阳大涨(7~9.5%)** | -8 | **大涨次日接力困难** |
| **放量下跌(量比>1.5，跌幅>3%)** | -5 | **资金出逃** |
| **缩量阴跌(量比<0.8，跌幅-2~-5%)** | +2 | **阴跌中，轻微加分空间** |
| **放量涨停(≥9.5%)** | -12 | 同上 |
| **大幅下跌(跌幅< -5%)，放量或缩量** | -8 | 趋势破坏 |

> 这个评分完全消除"涨停票在量价维度拿高分"的可能性——涨停票T日状态拿-12分。

#### 技术结构评分（12分）← 重写

从"均线层级越高分越高"改为"均线排列健康度+位置合理性+支撑有效性"：

| 子维度 | 满分 | 逻辑 |
|--------|:----:|------|
| 均线排列 | 5分 | 多头排列(MA5>MA10>MA20)→+5, 胶着→+3, 空头→0 |
| 位置评估 | 4分 | 价格在20日区间下1/3→+4（低位安全）, 中间→+2, 上1/3且未涨停→0, 涨停→-2 |
| 回调位置 | 3分 | 缩量回踩不破MA5/MA10/MA20→+3, 回踩MA20缩量企稳→+2, 破MA20→-2 |

**关键变化**：v6的"价格在MA5/MA10/MA20之上层级越高分越高"导致涨停票也拿高分（涨停价格自然在所有均线之上）。v7改为：**低位加分、高位不涨甚至是涨停扣分**。

#### 量能健康度（6分，精简）

| 量比范围 | 得分 | 说明 |
|:--------:|:----:|------|
| 1.5~3.0 | 6 | 活跃健康（放量启动的典型区间） |
| 0.8~1.5 | 4 | 温和正常 |
| >3.0 | 2 | 过热（可能是一致性出货） |
| 0.5~0.8 | 3 | 缩量（回调期正常） |
| <0.5 | 0 | 流动性枯竭 |

### 5️⃣ 大盘环境评分（score_market.py，10分）

### 7️⃣ 涨停观察池（zt_observation_pool.py）← 新增

**新增模块**。所有涨停票（无论什么策略模式）单独输出为"涨停观察池"，不进入精选。

目的：
1. 涨停票仍然有价值——作为次日竞价参考
2. 区分"选股"和"竞价"：涨停观察池告诉你"明天看哪些"；精选买入池告诉你"明天买哪些"
3. 涨停观察池的票如果次日低开/平开（从涨停回落），在竞价时仍然可以关注——但这不归选股系统管

```
涨停观察池构建规则：
  所有满足候选条件 + 当天涨停(≥9.5%) + 无一票否决
  → 输出为zt_observation: [{code, name, industry, board_times, seal_time, total_score}]
  
  zt_observation中的票仍然计算完整评分，但：
  - T日状态评分固定为 -12（涨停扣分）
  - 不进入精选TOP5
  - 在报告模版中单独一段"🌩 涨停观察池（参考）"
```

### 8️⃣ 策略中枢 ← 修正候选条件

v6的候选池条件需要修改——所有策略都不再要求"近5日必须涨停"：

| 策略 | v6候选条件 | v7候选条件 | 变化 |
|------|-----------|-----------|:----:|
| 强主线趋势 | 近5日有涨停+主线上+5亿成交+50亿市值 | **近10日有涨停**（任一交易日）+主线上+3亿成交+30亿市值 | **放宽涨停条件、降低门槛** |
| 主线回调低吸 | 近5日有涨停+主线上+3亿成交+30亿市值+从高点回撤<15% | **近10日有涨停**（任一交易日）+主线上+2亿成交+20亿市值+从高点回撤<20% | **放宽，龙头回踩常态缩量** |
| 无主线轮动 | 近5日有涨停+3亿成交+30亿市值 | **近15日有涨停**+2亿成交+20亿市值 | **轮动期范围更宽** |

**关键变化**：候选条件从"近5日有涨停"改为"近10日/近15日有涨停（任一交易日即可）"。这样昨天涨停今天回调的票也能进入候选，不会被挡在门外。

### 9️⃣ 综合评分计算

```
// 1. 基础评分（满分100）
base_score = score_renqi(25) + score_zhuxian(25) + score_state_liangjia(30)
           + score_market(10) + score_risk(10)

// 2. v6式的策略权重调节
scores = {
  renqi: base_renqi * (w_renqi/25),
  zhuxian: base_zhuxian * (w_zhuxian/25),
  state_liangjia: base_state_liangjia * (w_sl/30),
  market: base_market * (w_market/10),
  risk: max(0, base_risk) * (w_risk/10),
}
total_weighted = sum(scores.values())
total_weighted = max(0, min(100, total_weighted))

// 3. ★ T日状态最终修正 ★
// T日状态修正已在 score_state_liangjia 的 T日状态评分中体现
// 但额外增加精选保护：T日涨幅≥9%的票直接从精选剔除
final_total = total_weighted

// 精选规则：
// - T日涨幅≥9% → 自动从精选排除（放入涨停观察池）
// - 总评分排序前5 → 精选
// - 无一票否决 → 通过
// - 如果前5中有T日涨幅≥9%的，跳过，递补
```

### 🔟 精选(is_pick)规则

```
精选 = 满足以下条件的前5名：
  1. 候选条件通过
  2. T日涨幅<9%（排除涨停和准涨停）
  3. 无一票否决（ST/退市/停牌）
  4. 按 final_total 评分排序前5
```

## 与v6的关键对比

| 维度 | v6 | v7（修正版） |

## 验收标准（v7）

| # | 标准 | 验证方式 |
|---|------|----------|
| 0 | 精选TOP5中**0%**为T日涨停/大涨(≥9%)票 | 运行验证 |
| 1 | 入选票T+1上涨概率≥55%（大盘>-0.5%时） | 运行10个交易日统计 |
| 2 | 入选票3日上涨概率≥60% | 运行10个交易日统计 |
| 3 | 属于主线板块的入选票占比≥50% | 运行10个交易日统计 |
| 4 | 主线板块识别覆盖度核心板块正确识别≥80% | 回测30个交易日 |
| 5 | 涨停观察池正常输出，不与精选混叠 | 单次运行验证 |
| 6 | 精选数量稳定3-5只 | 单次运行验证 |
| 7 | 无新增外部API依赖 | 代码审查 |
| 8 | `daily_pick_v3.py`可独立运行 | 运行验证 |
| 9 | 选股结果正确落库 | 检查daily_picks表 |

**验收标准0是最重要的门禁**——精选TOP5中出现任何一个T日涨停/大涨(≥9%)票，即视为v7修正失败。
