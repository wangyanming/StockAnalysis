## 1. 概述

本文档为 `close_task.py`（收盘复盘报告生成）第4点（昨日选股涨跌及复盘）和第5点（明日候选评分及操作）的展示格式调整提供技术方案。涉及 `_load_yesterday_picks`、`_build_react_data`、`_build_picks_data` 的数据结构改造，以及 `close_report_tpl.py` 的渲染模版修改。

- ❌ 不新增数据库查询（复用现有 daily_picks 表数据）
- ❌ 不涉及回测跑分关联

## 3. 第4点改法

### 3.1 数据来源

复用 `close_task.py` 中已有的两个函数：

1. **`_load_yesterday_picks(trade_date)`** — 已实现：
   - 查 `daily_picks` 表：`SELECT code, name, total_score, rank, highlights, source FROM daily_picks WHERE trade_date=<昨日选股日> AND is_pick=1`
   - 查 `stock_daily` 表：获取 T+1 日（选股日次日）开盘价 和 T+2 日（选股日后两天）开盘价
   - 计算收益率：`(T+2开盘价 - T+1开盘价) / T+1开盘价 × 100%`

2. **`_build_react_data(trade_date, yesterday_picks)`** — 已有的fallback，已包含：
   - `yesterday_picks` 列表已有 `change_pct`（收益率）字段
   - 根据 `total_score` 做 `score_groups` 分组 → 需改为新的 A/B/C 分组

```python
# ============ 第4点新增：总体统计 ============
ypicks = d.get('yesterday_picks', [])
if ypicks:
    # 1. 总体统计（仅 ≥60分）
    qualified = [p for p in ypicks if p.get('total_score', 0) >= 60]
    total = len(qualified)
    wins = sum(1 for p in qualified if p['change_pct'] > 0)
    losses = total - wins
    win_rate = round(wins / total * 100, 1) if total > 0 else 0
    max_gain = max((p['change_pct'] for p in qualified), default=0)
    max_loss = min((p['change_pct'] for p in qualified), default=0)
    
    # 渲染总体统计表
    parts.append("📌 总体统计（≥60分）")
    parts.append(f"总数: {total} 只")
    parts.append(f"盈利: {wins} 只 ｜ 亏损: {losses} 只")
    parts.append(f"胜率: {win_rate}%")
    parts.append(f"最大盈利: {max_gain:+.2f}% ｜ 最大亏损: {max_loss:+.2f}%")
    
    # 2. B/C/D 分组统计
    groups = {'B组（60~65分）': [], 'C组（65~70分）': [], 'D组（≥70分）': []}
    for p in ypicks:
        sc = p.get('total_score', 0)
        if sc < 60: groups['A组（<60分）'].append(p)
        elif sc < 65: groups['B组（60~65分）'].append(p)
        else: groups['C组（≥65分）'].append(p)
    
    for label, members in groups.items():
        if members:
            cnt = len(members)
            grp_wins = sum(1 for p in members if p['change_pct'] > 0)
            grp_wr = round(grp_wins / cnt * 100, 1)
            grp_avg = sum(p['change_pct'] for p in members) / cnt
            parts.append(f"{label}: {cnt}只 盈利{grp_wins}只 胜率{grp_wr}% 均{grp_avg:+.2f}%")
        else:
            parts.append(f"{label}: 该分组今日无数据")
```

## 4. 第5点改法

### 4.1 数据来源

从 `daily_picks` 表取**今天**的选股结果：

```sql
SELECT code, name, total_score, source, highlights, stock_name, `rank`
FROM daily_picks
WHERE trade_date = %s       -- 今日日期（收盘任务运行日期）
  AND is_pick = 1
ORDER BY total_score DESC
```

> **注意**：不需要关联回测跑分。第5点的候选数据直接来自当前 `_build_picks_data()` 中的 `pick_stocks_v2()` 结果（结果已入库到 daily_picks），只需从该表取今天的数据，按 B/C/D 分组取TOP3即可。

## 5. 风险与注意事项

### 5.1 边界情况

| 场景 | 处理方式 |
|------|----------|
| `pick_stocks_v2()` 返回 `scored` 为空 | `score_groups` 三个分组均为 `[]`，模版显示"该分组今日无候选股" |
| `pick_stocks_v2()` 异常 | `_build_picks_data()` 已有 try/except，取空列表 fallback |
| 某分组候选股为0只 | 显示"该分组今日无候选股"，分组标题保留 |
| 某分组候选股1只 | 正常展示，无需补齐到3只 |
| 当日是周末/节假日 | 收盘任务不会运行，无需特殊处理 |

### 5.2 不要改到1、2、3点

⚠️ **危险红线**：

| 文件 | 不变区域 |
|------|----------|
| `close_task.py` | 第1-3点的数据加载逻辑（指数、板块、涨停数据）完全不变 |
| `close_report_tpl.py` | 所有 `1️⃣ 大盘概况`、`2️⃣ 板块/涨停`、`3️⃣ 涨跌/成交额` 的渲染代码完全不变 |
| `close_task.py` | `pick_stocks_v2()` 的调用（line ~402）完全不变 |

**安全策略**：在 `close_report_tpl.py` 中添加一个明确的 section 守卫变量，或只在 `4️⃣` 和 `5️⃣` 两个 section 的渲染代码块中做修改，不改动前3个points的代码。
