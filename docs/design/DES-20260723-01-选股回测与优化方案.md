## 1. 背景与数据准备

### 1.1 手动统计范围

| 项目 | 值 |
|:----|:---|
| 统计区间 | 2026-06-16 ~ 2026-07-21 |
| 交易日数 | 24天 |
| 策略 | 每日最高分 → T+1开盘买入 → T+2开盘卖出 |
| 总收益 | 约 **+16%** |

### 1.2 评分分组分析

| 评分分组 | 次数 | 胜率 | 平均收益 | 数据可信度 |
|:-------:|:----:|:----:|:--------:|:--------:|
| <60（低分） | 9次 | **33%** | **-2.55%** | ✅ 样本充足 |
| 60~70（中分） | 11次 | **73%** | **+3.43%** | ✅ 样本充足，表现稳定 |
| ≥70（高分） | 4次 | 25% | -1.91% | ⚠️ 样本量小，结论待验证 |

### 1.3 核心诊断

**问题1：低分股拖累严重**
- 福日电子(59分)：-12.8%（最大回撤）
- 中超控股(58分)：-6.60%
- 低分组9笔中有6笔亏损 → 说明<60分的选股信号**噪音大于信号**

**问题2：高分股不稳定**
- 高分往往来自连板股（涨停接力）
- T+1一字板买不进 → T+2资金分歧被闷
- 4笔样本中3笔亏损 → 现有评分为连板效力过高

**问题3：回撤无控制**
- 没有止损机制，亏损不放大
- 连续亏损时不休息，亏后继续操作

### 1.4 数据调研与前提条件

回测前对全量数据进行了完整性调研，结论如下：

**回测区间确认**：2026-05-13 ~ 2026-07-23（跳过2026-06-19假期）
**总工作日**：约51个交易日

**数据完整性**：

| 数据表 | 覆盖范围 | 状态 |
|:------|:---------|:-----|
| stock_daily | 20181121 ~ 20260723（6119440条） | ✅ 全量覆盖 |
| daily_limit_up | 20260403 ~ 20260723（7562条） | ✅ 全量覆盖 |
| sector_performance | 5/13起90个行业全量+rank_type='all' | ✅ 完整（5/13前20~45条不完整，已跳过） |
| index_quotes | 5/6起，6/11缺4个指数 | ✅ 6/11指数已手工补录入库（szzs/szcz/hs300/cyb） |

**排除的交易日**：
- 2026-06-19：假期，stock_daily仅3200条，跳过
- 2026-05-06 ~ 2026-05-12：板块数据不足（仅20~45条，正常90条），已跳过

**选股逻辑重跑**：
- `daily_picks` 表中5/13~6月间存在多源混合（v2、v3、大成交、大阳线等），评分体系不一致
- 回测**不依赖 `daily_picks` 历史数据**，改为每日调用 `pick_stocks_v2()` 统一重跑
- 需要包装一个 `pick_stocks_v2_for_date(trade_date)` 函数，将引擎中的 `datetime.now()` 替换为指定交易日

### 1.5 改进方向（基于数据）


## 2. 回测方案设计

### 2.1 回测目标

1. **验证**：手动统计的结论是否在更大样本下（20260513~20260723共51个交易日）仍成立  
2. **量化**：每种优化策略的收益提升幅度  
3. **迭代**：找到最优的分段阈值、暂停参数、过滤条件  

### 2.2 回测区间

| 项目 | 值 |
|:----|:---|
| 开始 | 20260513（板块数据完整日） |
| 结束 | 20260723（最新交易日） |
| 跳过 | 20260619（假期） |
| 交易日数 | 约51个 |
| 样本量 | 约50笔交易（每日TOP1） |

### 2.3 回测框架架构

```
┌─────────────────────────────────────────┐
│           回测主控制器                     │
│  backtest_controller.py                   │
│  - 遍历每个交易日                          │
│  - 调用 pick_stocks_v2_for_date() 重跑选股 │
│  - 模拟交易                               │
│  - 汇总统计                               │
└────────────┬────────────────────────────┘
             │ 每日重跑选股
             ▼
┌─────────────────────────────────────────┐
│       选股引擎包装层（核心新增）           │
│  pick_stocks_v2_for_date(trade_date)     │
│  - 将engine中 datetime.now() 替换为指定日期│
│  - 所有数据查询按历史日期执行               │
│  - 返回 [{code, name, total_score, ...}]  │
└────────────┬────────────────────────────┘
             │ 读取历史数据
             ▼
┌─────────────────────────────────────────┐
│        已有数据源                                         │
│  - stock_daily: 日K线数据                                  │
│  - daily_limit_up: 涨停明细                               │
│  - sector_performance: 板块数据                            │
│  - index_quotes: 指数数据                                 │
└────────────┬────────────────────────────┘
             │ 计算
             ▼
┌─────────────────────────────────────────┐
│         交易模拟引擎                      │
│  模拟: T日评分 → T+1开盘买入              │
│        → T+2开盘卖出                     │
│  处理: 停牌/一字板/涨跌停                 │
└────────────┬────────────────────────────┘
             │ 写入
             ▼
┌─────────────────────────────────────────┐
│          backtest_picks 表               │
│  每笔交易一条记录                         │

└─────────────────────────────────────────┘
```

### 2.4 回测逻辑

```
功能: run_backtest(start, end, strategy_params)

对每个交易日(trade_date in [start, end]):
  1. 调用 pick_stocks_v2_for_date(trade_date) 获得当日候选全量
     → 返回带评分的结果 [{code, name, total_score, source, details...}]
  
  2. 按 total_score DESC 取最高分候选
     → 如同分选 code 最小的（确定性）
  
  3. 策略过滤
     → 根据 Strategy A/B/C/D 决定是否跳过
  
  4. 查下一个交易日
     → "SELECT MIN(trade_date) FROM stock_daily
        WHERE code = %s AND trade_date > %s"
     → 第一个 = T+1（买入日）
     → 第二个 = T+2（卖出日）
  
  5. 查询开盘价
     → "SELECT open, change_pct, volume FROM stock_daily
        WHERE code = %s AND trade_date = %s"
  
  6. 成交判断
     → 成交量>0 且 非一字涨停开盘 → 按 open 成交
     → 成交量=0 → 停牌，跳过
     → 开盘涨停(change_pct≥9.5且volume极低) → 买不进，跳过
  
  7. 计算收益率
     → profit_rate = (sell_open - buy_open) / buy_open
  
  8. 结果入库 → INSERT INTO backtest_picks
```

### 2.5 pick_stocks_v2_for_date() 包装函数设计

```python
"""
选股引擎包装层

将现有 pick_stocks_v2() 中所有 datetime.now() 替换为指定交易日。
核心思路：不修改原 engine 代码，而是通过 patch/参数注入方式
让所有数据查询走历史日期。
"""

def pick_stocks_v2_for_date(trade_date: str) -> List[Dict]:
    """
    在指定历史日期上运行选股引擎
    
    Args:
        trade_date: YYYYMMDD 格式，如 '20260513'
    
    Returns:
        [{'code', 'name', 'total_score', 'source', 'score_chip', 'score_money', ...}]
    """
    # 方案A（推荐）：在 engine 入口处 patch datetime.now()
    # 通过替换模块的 datetime.now 返回值，让所有子函数自动使用历史日期
    from unittest.mock import patch
    from datetime import datetime as dt
    
    # 构造模拟的"现在"
    fake_now = dt.strptime(trade_date, '%Y%m%d')
    
    with patch('core.analyzer.daily_pick_v2.datetime') as mock_dt:
        mock_dt.now.return_value = fake_now
        mock_dt.strftime = dt.strftime
        mock_dt.strptime = dt.strptime
        
        # 同时 patch scorer 和 build_candidate_pool 中的 datetime
        with patch('core.analyzer.scorer.datetime') as mock_scorer_dt:
            mock_scorer_dt.now.return_value = fake_now
            mock_scorer_dt.strftime = dt.strftime
            mock_scorer_dt.strptime = dt.strptime
            
            from core.analyzer.daily_pick_v2 import pick_stocks_v2
            result = pick_stocks_v2()
    
    return result


# 方案B（稳妥）：封装一个 TimeMachine 上下文管理器，确保所有 datetime.now 都走模拟时间
class TimeMachine:
    """时间模拟器，用于在回测时模拟历史日期"""
    
    def __init__(self, target_date: str):
        self.target = datetime.strptime(target_date, '%Y%m%d')
        self.patches = []
    
    def __enter__(self):
        # patch 所有涉及 datetime.now 的模块
        modules_to_patch = [
            'core.analyzer.daily_pick_v2',
            'core.analyzer.scorer',
            'core.fetcher.daily_fetch',
        ]
        for mod_name in modules_to_patch:
            try:
                p = patch(f'{mod_name}.datetime')
                mock_dt = p.start()
                mock_dt.now.return_value = self.target
                mock_dt.strftime = datetime.strftime
                mock_dt.strptime = datetime.strptime
                mock_dt.combine = datetime.combine
                self.patches.append(p)
            except Exception:
                pass
        return self
    
    def __exit__(self, *args):
        for p in self.patches:
            p.stop()
```

### 2.6 停牌/一字板处理

| 情况 | 处理方式 | 标记字段 |
|:----|:--------|:--------|
| T日该股成交量为0（停牌） | 跳过该日的选股结果 | `stop_reason`='停牌，跳过' |
| T+1开盘即涨停且成交量<30%均值 | 不买入，记录"一字板" | `stop_reason`='T+1一字板无法买入' |
| T+1开盘即跌停 | 不买入，记录"跌停开盘" | `stop_reason`='T+1跌停开盘' |
| T+2开盘涨停/跌停 | 以涨停价/跌停价模拟成交 | `sell_price`记涨停/跌停价 |

### 2.7 backtest_picks 表结构

```sql
CREATE TABLE IF NOT EXISTS backtest_picks (
  id              INT AUTO_INCREMENT PRIMARY KEY,

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='回测交易明细';
```

## 3. 选股优化策略

（与 v1.0 相同，包含策略A/B/C/D四个策略，内容不变）

### 3.1 策略A：分数门槛过滤（优先级：P0）

**触发条件**：`total_score < 60` 时该笔交易取消

**效果预测**（基于手工统计）：
- 去掉9次平均-2.55%的低分交易
- 总收益预估提升：约+23%（9次×2.55% / 总收益16% ≈ 23%）

**实现示例**：
```python
if total_score < SCORE_LOW:  # SCORE_LOW = 60
    sr = "分数<60不买入"
```

### 3.2 策略B：连续亏损暂停（优先级：P1）

**触发条件**：连续2次交易亏损，则休息1个交易日

**参数建议**：
- `max_consecutive_loss` = 2次
- `rest_days` = 1个交易日

**伪代码**：
```python
def should_trade(consecutive_loss_count, max_loss=2):
    if consecutive_loss_count >= max_loss:
        return False, f'连续{consecutive_loss_count}次亏损，暂停1日'
    return True, ''
```

### 3.3 策略C：中分段精选（优先级：P2）

**触发条件**：仅对`60 ≤ total_score < 70`的股票执行交易

**数据驱动依据**：
- 60~70分：11笔，胜率73%，均收益+3.43% ← 最佳区间
- <60分：9笔，胜率33%，均收益-2.55%
- ≥70分：4笔，胜率25%，均收益-1.91%

**风险**：手动统计中≥70分仅4笔，样本太小，必须回测验证后再定

### 3.4 策略D（可选）：高分检查（优先级：P3）

**触发条件**：`total_score ≥ 70` 时做额外检查

```python
def check_highscore(code, name, total_score, source, board_times):
    if total_score < 70:
        return True, ''
    risks = []
    if source == '涨停热点' and board_times >= 2:
        risks.append('连板接力风险')
    if len(risks) >= 1:
        return False, ';'.join(risks)
    return True, ''
```

### 3.5 策略组合测试方案

| 策略ID | 策略组合 | 说明 |
|:-----:|:--------|:-----|
| baseline | 无过滤 | 当前策略，全量最高分 |
| A | <60过滤 | 基础门槛 |
| B | 连续亏损暂停 | 风控 |
| A+B | <60过滤+连亏暂停 | **推荐首选** |
| A+B+C | A+B+中分段精选 | 激进优化，舍弃≥70 |
| A+B+C+D | 全量策略 | 完整方案 |

## 4. 交易规则优化

（与 v1.0 相同，包含以下内容不变）

### 4.1 "下一个交易日"定义
- T+1 = `SELECT MIN(trade_date) FROM stock_daily WHERE code=%s AND trade_date > %s`
- T+2 = `SELECT trade_date FROM stock_daily WHERE code=%s AND trade_date > %s ORDER BY trade_date LIMIT 1 OFFSET 1`

### 4.2 收益率计算口径
- 统一公式：(sell_open - buy_open) / buy_open × 100%
- 买价 = T+1开盘价，卖价 = T+2开盘价

### 4.3 停牌处理策略
- T+1停牌 → 跳过
- T+2停牌 → 顺延至复牌日开盘卖出

## 5. 数据表与计算

### 5.1 涉及的表及关系

```
stock_daily (日K线)
│
├──→ backtest_picks (回测结果，独立表，不碰生产)
│      batch_id, trade_date, code, name, total_score, source
│      strategy_group, entry_price, buy_date, buy_price
│      sell_date, sell_price, profit_rate, stop_reason
│
└──→ daily_picks (生产选股结果，回测不直接读取)
       （回测改为重跑 pick_stocks_v2_for_date() 获得等价数据）
```

**核心变更**：回测不再查询 `daily_picks`，改为调用重跑函数

### 5.2 核心查询模式

#### Q1：重跑选股 → 不查询 daily_picks，改调函数

```
candidates = pick_stocks_v2_for_date('20260513')
top1 = max(candidates, key=lambda x: x['total_score'])
```

#### Q2：下一个交易日查询（不变）

```sql
SELECT MIN(trade_date) AS next_date, open AS open_price
FROM stock_daily
WHERE code = %s AND trade_date > %s;
```

#### Q3：停牌检测

```sql
SELECT volume, open, close, change_pct
FROM stock_daily
WHERE code = %s AND trade_date = %s;
```

### 5.3 批量回测统计

```sql
-- 按策略分组汇总
SELECT 
  strategy_group,
  COUNT(*) AS total_trades,
  SUM(CASE WHEN profit_rate > 0 THEN 1 ELSE 0 END) AS wins,
  AVG(profit_rate) AS avg_profit,
  SUM(profit_rate) AS total_profit,
  MAX(profit_rate) AS max_profit,
  MIN(profit_rate) AS min_profit
FROM backtest_picks
WHERE batch_id = %s AND stop_reason IS NULL
GROUP BY strategy_group;

-- 按评分分组汇总
SELECT 
  CASE 
    WHEN total_score < 60 THEN '<60'
    WHEN total_score < 70 THEN '60~70'
    ELSE '>=70'
  END AS score_group,
  COUNT(*) AS cnt,
  SUM(CASE WHEN profit_rate > 0 THEN 1 ELSE 0 END) AS wins,
  AVG(profit_rate) AS avg_profit
FROM backtest_picks
WHERE batch_id = %s AND stop_reason IS NULL
GROUP BY score_group;
```

## 6. 开发计划

### 6.1 阶段划分

```
阶段1: 回测基础建设（第1天）
```

### 6.2 阶段详情

#### 阶段1：回测基础建设（P0，第1天）

| 任务 | 交付物 | 预计工时 |
