## 3. 数据采集流程

### 3.1 全量流程

```
① 获取所有A股代码列表
   └─ 从 stock_daily 取最新交易日全部code（约5000只）
   └─ 或用内置的板块配置取全量

② 并发拉取腾讯日K行情（20路并发，每路拉200只）
   └─ API: https://web.ifzq.gtimg.cn/appstock/app/fqkline/get
   └─ 参数: {tx_code},day,,,640,bfq
   └─ 解析每只的OHLCV、当日涨跌幅

③ 拉取市值/PE/PB/换手率
   └─ 腾讯行情接口同行返回 vol=手、amount=万元
   └─ 总市值=流通市值=腾讯日K中的 row[11] 等字段
   └─ PE/PB由腾讯接口同一次返回

④ 批量写入 intraday_stock（INSERT IGNORE，500条/批）

⑤ 拉取涨停数据
   └─ 复用现有 LimitUpAnalyzer 的 get_today_limit_up()
   └─ 写入 intraday_limit_up

⑥ 拉取同花顺板块
   └─ ak.stock_board_industry_summary_ths()
   └─ 写入 intraday_sector，并计算全市场排名

⑦ 拉取新浪指数
   └─ 新浪 hq.sinajs.cn 接口
   └─ 写入 intraday_index

⑧ 计算60日价格分位
   └─ 从腾讯日K数据的近60个交易日取最高/最低
   └─ position_60d = (close - 60d_low) / (60d_high - 60d_low) * 100
   └─ 回填 intraday_stock.position_60d
```

### 3.2 并发策略

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

# 20路并发，200只/批

batch_size = 200
batches = [codes[i:i+batch_size] for i in range(0, len(codes), batch_size)]

with ThreadPoolExecutor(max_workers=20) as executor:
    futures = {executor.submit(fetch_batch, batch): batch for batch in batches}
    for future in as_completed(futures):
        batch = futures[future]
        try:
            records = future.result()
            # 批量入库
        except Exception as e:
            logger.error(f"batch {batch[0]}..{batch[-1]} failed: {e}")
```

## 4. 选股评分算法

### 4.1 过滤链（顺序执行，任一不通过即淘汰）

```
过滤条件     | 阈值                   | 说明
-------------|------------------------|-----------------------------
ST/退市      | 代码不含ST，名称不含ST  | 正则过滤
新股         | 上市≥60日              | 从腾讯日K数据检查K线条数
涨停         | 当日涨幅 < 9.5%        | 排除已封板
跌停         | 当日涨幅 > -9.5%       | 排除已封跌停
涨幅区间     | 3% ≤ change_pct ≤ 7%  | 核心条件
PE合理       | PE > 0 且 PE < 200    | 排除亏损和极端高PE
大盘安全     | 上证>-2% AND 深证>-2% AND 创业板>-2%
60日位置     | position_60d ≤ 70     | 非顶部区间
```

### 4.2 评分维度

#### 日内强度（30分）

| 条件 | 得分 | 说明 |
|------|------|------|
| 涨幅 4%~5% | 30 | 最佳区间：不涨停但有充足动量 |
| 涨幅 3%~4% | 25 | 涨幅偏低但仍在启动区间 |
| 涨幅 5%~7% | 20 | 涨幅偏高但未涨停 |
| 涨幅差 | 减分 | 每偏离0.5%减3分 |

额外加分：成交量大于5日均量×1.2（+5分）

#### 板块热度（25分）

| 板块排名 | 得分 | 说明 |
|----------|------|------|
| 全市场第1-3名 | 25 | 最强热点 |
| 第4-6名 | 20 | 中等热点 |
| 第7-10名 | 15 | 一般热点 |
| 第11名+ | 0 | 淘汰（未进前10应该已被过滤链淘汰） |

#### 估值安全（20分）

| 条件 | 得分 | 说明 |
|------|------|------|
| PE 0~15 | 20 | 低估值 |
| PE 15~30 | 18 | 合理估值 |
| PE 30~50 | 15 | 偏高但可接受 |
| PE 50~100 | 12 | 偏贵 |
| PE 100~200 | 8 | 高估值 |
| PE ≤ 0 或 > 200 | 0 | 过滤链已淘汰 |

额外加分：PB < 2（+3分），PB < 1（+5分）

#### 位置评分（15分）

| 60日分位 | 得分 | 说明 |
|----------|------|------|
| 30%~50% | 15 | 最优区间：已脱离底部但未到顶部 |
| 50%~60% | 12 | 中等区间 |
| 15%~30% | 10 | 偏底部，可能趋势未确认 |
| 60%~70% | 8 | 偏高 |
| <15% | 5 | 弱势股，趋势未确认 |
| >70% | 0 | 过滤链已淘汰 |

#### 大盘环境（10分）

| 上证涨跌幅 | 得分 | 说明 |
|-----------|------|------|
| -1% ~ +0.5% | 10 | 最优环境 |
| -1.5% ~ -1% 或 +0.5%~+1.5% | 7 | 温和环境 |
| -2% ~ -1.5% 或 >+1.5% | 5 | 偏弱/过热 |
| ≤ -2% | 0 | 大盘风险（过滤链已淘汰） |

### 4.3 总分公式

```
综合评分 = 日内强度 + 板块热度 + 估值安全 + 位置评分 + 大盘环境
满分 = 30 + 25 + 20 + 15 + 10 = 100分
```

### 4.4 输出规则

- 取总分前5~10名
- 相同板块最多入选2只（防板块过度集中）
- 评分 < 50 的不输出

## 7. 错误处理与重试

### 7.1 分级降级策略

| 失败环节 | 降级策略 | 可选股？ |
|----------|----------|----------|
| 腾讯日K接口（全量个股） | 跳过全部，终止选股 | ❌ |
| 部分个股拉取失败 | 跳过该个股，不影响其他 | ✅（部分数据） |
| 涨停数据 | 不做涨停过滤 | ✅（降级，无涨停过滤） |
| 同花顺板块接口 | 不做板块热度过滤 | ✅（降级，无板块排名） |
| 新浪指数 | 视为大盘安全 | ✅（保守策略） |
| 60日均线计算 | position_60d 设为50%（保守中间值） | ✅ |

### 7.2 重试策略

- 腾讯日K接口：每批重试2次，间隔2秒
- 同花顺板块：重试3次（复用 existing pattern）
- 新浪指数：重试2次
- 数据库写入：重试2次，MySQL连接断开时自动重连

## 9. 改动风险评估

| 风险项 | 影响 | 缓解措施 |
|--------|------|----------|
| 全量个股并发拉取阻塞 | 耗时超5分钟 | 20路并发+超时控制 |
| 腾讯接口频率限制 | 部分股票返回空 | 重试+跳过机制 |
| 同花顺接口盘中不稳定 | 板块数据缺失 | 降级为不做板块过滤 |
| 大盘暴跌导致误选 | 选出下降趋势股 | 大盘风险过滤 |
| cron 14:30与15:10快照冲突 | 数据采集重叠 | 使用独立表，完全解耦 |
