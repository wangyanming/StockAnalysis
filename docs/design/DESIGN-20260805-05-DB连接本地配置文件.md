## 一、目标

在生产 / dev 运行环境都能连上真实数据库的前提下，**密码不进版本库**，同时**不依赖环境变量注入**。通过项目本地文件 `config/db_url.local.json` 存两套真实 DB URL，dao.py 按项目路径选 prod/dev，并纳入 .gitignore。

## 二、背景与问题

改造2（DESIGN-20260805-03）把 `utils/dao.py` 的数据库密码脱敏为 `***`，设计为运行时通过 `STOCK_DB_URL` 环境变量注入真实凭据。但实际部署发现缺口：

| 问题 | 现状 | 后果 |
|------|------|------|
| **运行环境未注入 STOCK_DB_URL** | 生产 / dev 的 `web_server.py` 启动、OpenClaw cron 任务均**没有**设置 STOCK_DB_URL | 运行时拿不到真实密码 |
| **源码密码 `***` 无法连库** | dao.py 兜底走 `_PROD_MYSQL_URL`/`_DEV_MYSQL_URL`，密码是 `***` | 连库报 `Access denied` |
| **明文密码留在 git 历史** | 旧版生产 dao.py（4196eca）把明文密码 `stock123` 写死并随 git 提交（历史遗留）；改造2 已脱敏，但 git 历史仍含明文 | 凭据泄露风险（已纳入改造，但历史提交无法抹除，只能在新文件层面杜绝继续写入） |

> 根因：脱敏后只预留了"运行时注入"一个通道，但部署侧没有按预期注入，导致生产环境直接连库失败。需要一套**部署侧预置、版本库外、不依赖环境变量注入**的凭据方案。

## 三、目标方案

在项目 `config/` 下新建本地文件 `db_url.local.json`，存两套 DB URL：

```json
{
  "db_url_prod": "mysql://root:***@127.0.0.1:3306/stock_analysis",
  "db_url_dev":  "mysql://dev_app:***@127.0.0.1:3306/stock_analysis_dev"
}
```

- **dao.py 启动时**按路径（含 `StockAnalysis-dev` → 用 dev，否则 → 用 prod）从该文件读对应 URL。
- **文件加入 .gitignore**，密码**不进版本库**（避免重蹈 4196eca 明文提交覆辙）。
- **生产 / dev 各放一份**，内容相同，由部署方各自预置真实密码。

> 说明：上面示例中的密码仍以 `***` 占位，实施时由生产 / dev 部署方在各自机器上的本地文件里填入真实密码；本地文件在 .gitignore 中，不会提交。

## 四、优先级设计

DB_URL 取值优先级（从高到低）：

```
1. config/db_url.local.json 存在且可解析 → 按路径判定选 prod/dev（最高优先）
2. STOCK_DB_URL 环境变量显式设置      → 用环境变量（兼容临时注入）
3. 默认走现有 _default_mysql_url() 路径判定 → _PROD_MYSQL_URL / _DEV_MYSQL_URL（保持脱敏 ***，仅兜底）
```

**理由**：
- `config/db_url.local.json` 是**部署侧预置**的本地文件，密码在版本库外；`STOCK_DB_URL` 只作为临时覆盖通道保留（兼容调试/临时指向其它库）。
- **不依赖 cwd / 环境变量**：OpenClaw cron 任务以 `cd 项目根 + python3 xxx.py` 方式运行，**不设置环境变量**。因此本地配置文件必须能稳定定位——dao.py 用 `__file__` 上溯定位 `config/` 目录（同改造2 的 `_PROJECT_ROOT` 思路），不依赖进程的 cwd。
- 最兜底仍是现有 `_PROD_MYSQL_URL`/`_DEV_MYSQL_URL`（脱敏 `***`），保证文件缺失 / 解析失败时**不抛异常、能回退**，但此时连库会失败（Access denied），作为显式告警信号。

## 五、改动清单

### A. 新增本地配置文件（版本库外）
- **`config/db_url.local.json`**（生产机器 + dev 机器各放一份，内容相同，密码各写真实值）
- 结构见"三、目标方案"，键名固定 `db_url_prod` / `db_url_dev`

### B. `.gitignore` 增加排除
- 追加一行 `config/db_url.local.json`，确保本地文件不进版本库

### C. `utils/dao.py` 新增逻辑
1. 新增 `_load_db_url_from_local_config() -> Optional[str]`：
   - 用 `_PROJECT_ROOT`（`__file__` 上溯一级）拼接 `config/db_url.local.json` 绝对路径，**不依赖 cwd**
   - 文件不存在 / JSON 解析失败 / 键缺失 → 返回 `None`（静默回退，不抛异常）
   - 文件存在且可解析 → 按 `"StockAnalysis-dev" in _PROJECT_ROOT` 路径判定，取 `db_url_dev` / `db_url_prod`
2. 调整 `DB_URL` 优先级：
   ```python
   _LOCAL_DB_URL = _load_db_url_from_local_config()
   if _LOCAL_DB_URL:
       DB_URL = _LOCAL_DB_URL                      # 1. 本地配置文件（最高优先）
   else:
       DB_URL = os.environ.get("STOCK_DB_URL", _DEFAULT_MYSQL_URL)  # 2/3. env / 路径兜底
   ```
3. **保留**：`_default_mysql_url()` 路径判定、`_PROD_MYSQL_URL`/`_DEV_MYSQL_URL`（脱敏 `***`，仅兜底）、unix_socket 逻辑、连接池参数（5/1）
4. 更新文件顶部 docstring：把"环境变量 & 路径判定"优先级改为"本地配置文件 > 环境变量 > 路径判定"三段描述
5. `import json`（新增标准库 import）

### D. 文档同步
- `PROJECT_STATE.md` 数据库章节：注明"凭据由 config/db_url.local.json 本地文件提供（版本库外、.gitignore），dao.py 按项目路径选 prod/dev"

4. **STOCK_DB_URL 覆盖**：设 `STOCK_DB_URL` 且本地文件存在时，应确认优先级为本地文件最高（即本地文件优先）；本地文件**缺失**时，env 才能覆盖

## 九、风险

- **风险-1：本地文件落入版本库** → 已加 .gitignore；若已误提交，`git rm --cached config/db_url.local.json` 后重新预置
- **风险-2：本地文件缺失/损坏导致连库失败** → 设计为静默回退到脱敏 `***`，不抛异常但会 Access denied；靠第 6 条验证保障回退不报错
- **风险-3：密码散落多机** → 生产 / dev 各放一份，内容相同；约束为只在本地 .gitignore 文件中维护
- **风险-4：路径判定依赖目录名** → 沿用改造2 的 `_PROJECT_ROOT`（`__file__` 上溯，非 cwd），与既有判定一致

- 生产 / dev 各放一份本地文件（内容相同）
