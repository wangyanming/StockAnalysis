# 方案设计：商业基本面分析 Agent (DES-20260617-01)

## 1. 模块定位
新增 `core/analyzer/fundamental_analyzer.py`，作为独立工具模块，**不嵌入选股流程**，供主人按需调用。

## 2. 架构设计

```
┌─────────────────────┐
│  fundamental_       │  ← 入口类
│  analyzer.py        │
├─────────────────────┤
│  CompanyProfile     │  ← 基本信息/主营业务
│  FinancialAnalyzer  │  ← 财务分析
│  ValuationAnalyzer  │  ← 估值分析
│  ShareholderAnalyzer│  ← 股东分析
│  ReportGenerator    │  ← 报告组装
└─────────────────────┘
```

## 3. 数据获取策略

### 3.1 AKShare 接口方案
AKShare 提供较完善的基本面数据接口：

| 功能 | AKShare 函数 | 返回字段 |
|------|-------------|---------|
| 公司简介 | `stock_info_company` | 主营业务、成立日期、上市日期、高管 |
| 利润表 | `stock_profit_sheet_by_report_em` | 营收、净利润、扣非净利润 |
| 资产负债表 | `stock_balance_sheet_by_report_em` | 总资产、总负债、应收账款 |
| 现金流量表 | `stock_cash_flow_sheet_by_report_em` | 经营现金流净额 |
| 财务指标 | `stock_financial_abstract_ths` | ROE、毛利率、净利率 |
| 股东信息 | `stock_fund_holder` | 机构持仓 |
| 估值 | 腾讯实时+日线推算 | PE、PB |

### 3.2 缓存策略
- 财务数据按季度缓存（`_cache` dict，生命期单次分析）
- 同一天多次查询同一只票不走AKShare（减少请求）
- 失败时返回 `None`，报告标记「数据暂缺」

### 3.3 容错
- 每个数据源独立 try/except
- 部分数据获取失败不影响整体报告
- 关键字段缺失在报告中标明

## 4. 报告格式（Markdown）

### 4.1 模板
```
# 📊 基本面分析：{股票名称}({代码})

## 1️⃣ 公司概览
- 全称：xxx
- 上市板块：xxx
- 总市值：xxx亿
- 主营业务：xxx（收入占比%）

## 2️⃣ 产业链定位
- 上游：xxx
- 下游：xxx
- 毛利率：xxx（反映话语权）
- 应收账款/营收：xxx（回款能力）

## 3️⃣ 财务分析
| 年份 | 营收 | 增长 | 净利润 | 增长 | 毛利率 | 净利率 | ROE | 负债率 |
|------|------|------|--------|------|--------|--------|-----|--------|
解读：增长趋势、盈利能力变化

## 4️⃣ 估值对比
- PE(TTM)：xxx，行业中位数：xxx
- PB：xxx
- 历史PE分位：xxx

## 5️⃣ 股东分析
- 前十大股东占比：xxx
- 机构持仓变化：基金增减情况
- 增减持动态：xx

## 6️⃣ 综合评价
⭐ 评级：x/5
看法：一句话
```

## 5. 评分规则（星级）
| 维度 | 权重 | 评分依据 |
|------|------|---------|
| 财务健康度 | 30% | 营收增长趋势、ROE>10%、负债<60%、经营现金流为正 |
| 成长性 | 25% | 近3年营收CAGR、净利润CAGR |
| 估值合理性 | 25% | PE处于历史中低位、PE低于行业 |
| 产业链地位 | 20% | 毛利率行业领先、应收账款周转好 |
→ 总分≥90为一星
