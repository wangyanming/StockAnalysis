# 需求文档

**版本:** v1.0
**日期:** 2026-05-27
**状态:** 已定稿

---

## 1. 需求背景

- **提出人:** 主人
- **相关模块:** 分析/报告
- **解决的问题:** pick_react.py 的 Observe→Thought→Act 三闭环未能集成到每日收盘复盘报告中，现有的 _build_react_data() 是简化版，缺失 Thought 归因分析和 Act 建议输出

## 2. 功能范围

### 2.1 做（Scope In）
- 在 close_task.py 中调 pick_react.run_react_analysis() 替代 _build_react_data()
- 输出格式包含：Observe 统计（胜率/涨幅分布）→ Thought（评分维度归因，近30天各维度预测力分析）→ Act（权重调整建议）
- 保留现有的评分分组（高分/中分/低分）和推荐分组（涨停接力/区间潜伏）统计
- 保留近一周历史统计
- close_task.py 输出改为直接返回文本，由 close_report_tpl.py 渲染

### 2.2 不做（Scope Out）
- 不自动应用权重调整（需要主人确认后才应用）
- 不改动 scorer.py 代码
- 不改动现有 MySQL 表结构

## 3. 详细说明

### 3.1 输入
- pick_react.run_react_analysis(check_date)：直接从 DB（observe_log + daily_picks + stock_daily）取数据
- close_task.py 原来从 _load_yesterday_picks() 获取的数据

### 3.2 输出
- 格式化文本段落，追加到复盘消息的第4段尾部
- 包含 Observe 统计、Thought 归因表格、Act 建议

### 3.3 处理逻辑
```
close_task.py Run analysis final
  ↓ 第795行改
pick_react.run_react_analysis(check_date)
  ↓
  Observe: 从 daily_picks 获取昨日候选 + 次日表现
  Thought: _dim_accuracy_analysis() 按评分维度归因（近30天）
  Act: generate_act_suggestions() 输出权重调整建议
  ↓
返回多行文本 → 拼到复盘消息
```

### 3.4 边界条件
- 昨日无候选数据 → 输出"暂无昨日候选"，不报错
- observe_log 表为空 → 跳过 Thought 归因
- 近30天数据不足 → 归因显示可用的实际天数
- pick_react 内部异常 → close_task 捕获，回退到简版统计

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| **时效性** | 收盘复盘时额外耗时 < 3 秒 |
| **稳定性** | pick_react 异常不影响整份复盘报告生成 |
| **可观测性** | 日志输出 ReAct 分析耗时和数据条数 |

## 5. 依赖关系

- **前置需求:** 无
- **外部依赖:** observe_log 表（pick_react 当前已写入）
- **配置项:** 无

## 6. 测试要点

- 正常流程：close_task 完整执行，ReAct 三段输出正常
- 无数据：observe_log 为空时降级良好
- pick_react 异常：close_task 回退到简版统计并打日志
- 输出格式：复盘推送中 ReAct 段落在第4段末尾可见
