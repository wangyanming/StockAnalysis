# 需求文档：Web 前端对齐产品原型

**版本:** v1.0
**日期:** 2026-07-16
**状态:** 草稿

## 1. 背景

当前 Web 前端 `web_app.html`（上线版）与产品原型 `web_prototype.html` 存在多处不一致，包括成交额单位、涨跌家数显示、选股追踪布局。

## 2. 修改项

### 2.1 成交额单位格式化

**问题：** 前端直接显示原始数字 `2,587,412,000,000`，不可读。

**原型要求：**
```
总成交额: 0.26万亿（较昨日 -0.13万亿）
```

**改法：** 在 `fmt()` 工具函数外新增一个专门格式化成交额的函数，将 `元` 单位的原始数字转换为 `亿` 或 `万亿`：
- ≥ 10000 亿 → 显示 `X.XX万亿`
- < 10000 亿 → 显示 `X,XXX亿`

涉及：`web_app.html` 的 `fmtAmount()` 函数 + `loadMarketSummary()` 中调用

### 2.2 涨跌家数显示精简

**问题：** 当前显示 `上涨 3351 · 下跌 2098 · 平盘 0 · 合计 5449`，多出平盘和合计。

**原型要求：**
```
上涨 3351 · 下跌 2098
```

**改法：** `loadMarketSummary()` 中只渲染 `rise_count` 和 `fall_count`，去掉 `flat_count` 和合计行。

### 2.3 选股追踪对齐原型

**问题：** 当前展示为卡片布局，与原型表格式不同。

**原型要求（`web_prototype.html` 选股表格）：**

| 代码 | 名称 | 维度 | 入选日 | 评分 | 入选价 | T+1 | T+2 | T+3 | T+4 | T+5 |
|------|------|------|--------|------|--------|-----|-----|-----|-----|-----|
| 600123 | 龙头股份 | 涨停接力 | 07-15 | 85 | 22.50 | — | — | — | — | — |

**具体改动：**

| # | 改动 | 说明 |
|---|------|------|
| 1 | 卡片布局 → **表格布局** | 与原型一致，10列：代码、名称、维度、入选日、评分、入选价、T+1~T+5 |
| 2 | 增加**入选价**列 | 需从 `/api/picks` 中获取 `entry_price` 字段（若无则显示 "--"） |
| 3 | 增加**入选日**列 | 显示 `MM-DD` 格式 |
| 4 | 维度中文映射 | `limitup` → 涨停接力，`range` → 区间潜伏 |
| 5 | T+N 涨跌幅 | 有数据时显示 `+3.2%` / `-1.2%`，无数据时显示 `—` |
| 6 | 分页功能 | 每页 10/20/50/100 条，上下翻页 |
| 7 | 无数据提示 | 保持现有 "当日无选股数据" |

### 2.4 前端文件
仅改 `web_app.html`，不改后端 API

## 3. 接口依赖

### `/api/picks?date=&tag=`
当前返回字段：
```json
{
  "picks": [{
    "code": "600123",
    "name": "龙头股份",
    "data_tag": "limitup",
    "total_score": 85,
    "dimensions": { "score_chip": ..., ... },
    "tracking": [{"date":"...", "change_pct": 0.5}, ...]
  }]
}
```

**需新增字段：** `entry_price`（入选价格），如果后端没有则前端显示 "--"

## 4. 验证标准

1. 成交额显示 `X.XX万亿` 或 `X,XXX亿` 格式
2. 涨跌家数仅显示"上涨 X · 下跌 X"
3. 选股追踪为 10列表格格式，有分页
4. 三个模块切换正常，无 JS 错误
