# ReAct复盘改版 —— 20日胜率统计与评分归因

**版本:** v1.1
**日期:** 2026-07-27
**状态:** 已评审
**负责角色:** PDAgent（需求&原型）→ SAAgent（技术方案）→ RDAgent（开发）

---

## 1. 背景

当前收盘复盘报告第4段的 ReAct 复盘部分，展示的是**当日选股统计**（即 T-2 日选股的单日表现：总数、胜率、均涨幅等）。这个视角的问题是：

1. **样本量小**：单日选股样本量通常只有几只，统计意义有限；
2. **波动大**：单日表现受大盘情绪影响严重，无法真实反映模型稳定性；
3. **缺少归因**：不知道每个评分维度的预测能力——什么维度打分高时真的涨了、什么维度是虚高。

因此需要将 ReAct 复盘改为**近20个交易日的滚动窗口**，在更大样本池上做胜率统计和评分归因分析。

---

## 2. 时间范围定义

| 符号 | 含义 | 示例 |
|------|------|------|
| T | 报告日（复盘推送日） | 2026-07-27 |
| T-2 | 最近的选股入库日 | 2026-07-23（假设 7/25-26 是周末） |
| 窗口 | T-2 往前推19个交易日，共20个有 `daily_picks` 数据的交易日 | 含 T-2 在内共20天 |

**窗口示意图：**

```
交易日:  [D₁] [D₂] [D₃] ... [D₁₉] [D₂₀=T-2] → [报告日=T]
              ←──── 20个选股日 ────→          ↑
                                              不做选股日统计
```

**关键规则：**

- 统计 `daily_picks` 表中 `total_score ≥ 60` **全部个股**（无需 `is_pick=1` 条件）
- 不足20天怎么办：有多少算多少，但标注"仅X天数据"
- 若某一天的统计范围内无任何满足筛选条件的记录，则跳过该天

## 3. 收益率公式（已确认）

计 算 公 式 （ `_load_yesterday_picks()` 中已有实现）:

```
收益率 = ((T+2收盘价) - (T+1开盘价)) / (T+1开盘价) × 100%
```

| 时间点 | 含义 | 数据来源 |
|--------|------|----------|
| T | 选股入库日（daily_picks.trade_date） | daily_picks |
| T+1 | T 之后第一个交易日 | stock_daily（取 open） |
| T+2 | T+1 之后下一个交易日 | stock_daily（取 close） |

**重要前提：在改版前必须先修复 `_fill_next_day_change()` 的收益率计算！**

当前 `pick_react.py` 中 `_fill_next_day_change()` 计算的是 `(T+1收盘 - T收盘) / T收盘`，**与目标公式不匹配**。改版前必须先修正这个函数，使 `daily_picks.next_day_change` 和 `observe_log.next_day_change` 都按目标公式计算。

改版后应尽量复用 `observe_log` 表的统计（速度快、口径统一）。

## 4. 统计内容详述

### 4.1 胜率统计（概览）

**全局统计（20天合计）：**

| 指标 | 定义 | 计算方式 |
|------|------|----------|
| 总只数（n） | 20天内所有 `total_score ≥ 60` 的个股汇总数量 | COUNT(*)（无需 `is_pick=1`） |
| 盈利只数（wins） | ((T+2收盘价) - (T+1开盘价)) > 0 的票数 | SUM(IF(close>open,1,0)) 或 SUM(IF(next_day_change>0,1,0)) |
| 胜率（WR） | wins / n × 100% | 保留1位小数 |
| 平均收益率 | AVG(收益率) | 保留2位小数，带+/-号 |

> 不再展示按天趋势（20行过长，决定去掉）

### 4.2 评分归因分析

**核心问题：每个评分维度打分高的时候，股票是不是真的涨了？**

#### 4.2.1 涉及的维度

| 维度 | 字段名（daily_picks） | 满分 | 备注 |
|------|----------------------|------|------|
| 筹码结构 | score_chip | 25 | 0-25分，✅ 数据完整 |
| 资金接力 | score_money | 25 | 0-25分，✅ 数据完整 |
| 板块环境 | score_sector | 20 | 0-20分，✅ 数据完整 |
| 趋势位置 | score_trend | 20 | 0-20分，✅ 数据完整 |
| 大盘安全 | score_market | 10 | 0-10分，✅ 数据完整 |

> **位置评估（score_pos）本次暂不纳入归因**。当前 `daily_pick_v2.py` 未写入该字段，待后续数据完备后再补充。

#### 4.2.2 分析逻辑

对每个维度，将总分按**合理区间分段**，统计每个分数区间内所有票（跨20天）的：

| 指标 | 定义 |
|------|------|
| 样本数 | 该区间内的票数 |
| 胜率 | 该区间内收益率>0的票占比 |
| 均收益率 | 该区间内收益率的平均值 |

**区间分段方案（建议）：**

| 维度 | 满分 | 建议区间 |
|------|------|----------|
| 筹码结构 | 25 | 高分≥15、中分5~14、低分<5 |
| 资金接力 | 25 | 高分≥15、中分5~14、低分<5 |
| 板块环境 | 20 | 高分≥12、中分4~11、低分<4 |
| 趋势位置 | 20 | 高分≥12、中分4~11、低分<4 |
| 大盘安全 | 10 | 高分≥6、中分3~5、低分<3 |

#### 4.2.3 "预测正确率"定义

> 某维度打高分时，票实际收益率为正 → 该维度在此次预测中"正确"。

**计算公式（对于单个维度D）：**
```
D的高分预测正确率 = (D得分≥高分阈值 且 收益率>0 的票数) / (D得分≥高分阈值 的总票数) × 100%
```

**汇总输出（每个维度）：**

| 输出项 | 说明 |
|--------|------|
| 维度名称 | 如"筹码结构" |
| 高分窗口胜率 | 高分区间内的胜率 |
| 高分窗口样本数 | 高分区间内的票数 |
| 中分窗口胜率 | 中分区间的胜率 |
| 低分窗口胜率 | 低分区间的胜率 |
| 预测区分度 | 高分胜率 − 低分胜率，越大说明该维度越有区分力 |
| 结论 | 强/中/弱：该维度是否有预测能力 |

**盈利判断标准**（与概览一致）：
```
盈利 = ((T+2收盘价) - (T+1开盘价)) > 0
收益率 = ((T+2收盘价) - (T+1开盘价)) / (T+1开盘价) × 100%
```

### 4.3 B/C/D分组统计（保持与现有一致）

| 分组 | 评分区间 |
|------|----------|
| B组 | 60 ≤ total_score < 65 |
| C组 | 65 ≤ total_score < 70 |
| D组 | total_score ≥ 70 |

统计指标：样本数、盈利只数、胜率、均收益率。

## 7. 不足20天数据处理

| 场景 | 处理方式 |
|------|----------|
| 系统刚上线，数据 < 5天 | 提示"数据样本过少（仅X天），暂不展示归因分析"，仅展示概览 |
| 数据 5~19天 | 正常展示，标题标注"仅X天数据" |
| 数据 ≥ 20天 | 完全展示，标题标注"20交易日" |
| 个别维度某区间样本数为0 | 该维度该区间显示"无样本" |

**技术判断逻辑：**
```python
def get_active_pick_dates(check_date: str, max_days: int = 20) -> list:
    """获取有完整 observe_log 数据的交易日列表"""
    rows = db.fetchall("""
        SELECT DISTINCT trade_date FROM observe_log
        WHERE trade_date < %s AND next_day_change IS NOT NULL
        ORDER BY trade_date DESC LIMIT %s
    """, (check_date, max_days))
    return [r['trade_date'] for r in rows]
```

## 8. 与现有 ReAct 三闭环的关系

**现有 `pick_react.py`** 中 `run_react_analysis()` 已经实现了：
- Observe（补全次日涨跌幅）
- Thought（维度归因分析，`_dim_accuracy_analysis()`）
- Act（权重调整建议，`generate_act_suggestions()`）

但当前的分析周期是**近30天`observe_log`**、归因窗口较小、使用的区间分段是硬编码的高/中/低三段。

**改版方案：**

| 项目 | 当前 | 改版后 |
|------|------|--------|
| 统计窗口 | 近5日（表现概览）+ 近30日（归因） | 统一近20个**有效选股日** |
| 数据源 | daily_picks（部分）+ observe_log（归因） | observe_log 为主 |
| 收益率口径 | 不统一（部分用 next_day_change，部分后来计算） | 统一用 `next_day_change`（即(T+2收盘−T+1开盘)/T+1开盘） |
| 归因维度数 | 5（不含位置评估） | 5（不含位置评估，score_pos暂不纳入） |
| 渲染输出 | pick_react.py 返回纯文本，tpl.py 中直接插入 | 统一在 close_task.py 或新模块中数据计算，tpl.py 渲染 |

**建议方案**：改造 `run_react_analysis()` 函数，使其输出结构化 dict 而非纯文本，然后在 `close_report_tpl.py` 中渲染。保留三闭环分析逻辑（Thought+Act的归因结论和权重建议）作为补充段落拼接在底部。

## 11. 验收标准

### 11.1 胜率统计验收
1. 概览展示总只数、盈利只数、胜率、均收益率，数值正确
2. 不足20天时正确标注数据天数

### 11.2 评分归因验收
1. 每个维度展示高/中/低三段的分段胜率和均收益率
2. 区分度计算正确（高分胜率−低分胜率）
3. 位置评估暂不纳入，评分归因仅展示5个维度

### 11.3 B/C/D分组验收
1. B/C/D三组样本数、胜率、均收益率正确
2. 分组边界准确（60/65/70）

### 11.4 渲染验收
1. 输出格式清晰可读，符号（🟢/🟡/🔴）正确映射
2. 与报告第4段其他内容（T-2日选股涨跌及复盘）不冲突
3. 在推送/终端查看时无换行错位
