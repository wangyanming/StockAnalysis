# 复盘报告第4点、第5点展示格式调整

**版本:** v1.0
**日期:** 2026-07-24
**状态:** 待评审
**负责角色:** PDAgent（需求&原型）→ SAAgent（技术方案）→ RDAgent（开发）

---

## 1. 背景

现有收盘复盘报告（`close_task.py` → `close_report_tpl.py` 渲染）中，第4点"昨日选股涨跌及复盘"和第5点"明日候选评分及操作"的展示格式为最早版本沿用至今，存在以下问题：

1. **第4点**：标题不够直观，内容仅按个股逐一罗列再汇总，缺少分组维度的表现统计。用户需要快速了解昨日选股在不同组别（A/B/C 三组）的表现差异，以及"T-2日选股"整体统计指标（总数、盈利、亏损、胜率、最大盈利、最大亏损），目前的汇总展示过于简单。
2. **第5点**：明日候选推荐目前按"涨停接力TOP5 + 区间潜伏TOP5"两个固定板块展示，但用户希望改为 **按B、C、D评分分组展示**，每组按评分降序取TOP3，更直观地对比不同评分区间的推荐质量。

本次需求旨在调整这两部分的展示格式，让复盘报告更具信息密度和决策参考价值。

---

## 2. 当前问题

### 2.1 第4点问题

- 标题"昨日选股涨跌及复盘"未体现统计口径（是T-2日选股的涨跌）。
- 内容按个股逐一罗列，虽然也有汇总，但**缺少分组统计**（用户需要知道A组、B组、C组各自的胜率和收益）。
- **总体统计指标不够详细**：当前仅展示"上涨/下跌/胜率"，缺少最大盈利、最大亏损。

### 2.2 第5点问题

- **展示维度与用户期望不一致**：当前按"涨停接力 / 区间潜伏"两个策略类型分组展示TOP5，用户期望改为**按B/C/D评分分组展示TOP3**。
- **缺少空分组处理逻辑**：若某一分组当日无候选股，当前没有清晰的缺省提示。
- 候选股数量不足3只时，按固定TOP5展示会展示过少，但当前无动态适配逻辑。

---

## 3. 详细需求说明

### 3.1 第4点调整需求

**标题改**：从"昨日选股涨跌及复盘"改为 **"T-2日选股涨跌及复盘"**。

**内容结构改为以下三段式**：

#### a. 总体统计

展示以下指标（数据来源于前一选股日的选股结果，按 T+1 开盘买入、T+2 开盘卖出的口径统计）：

| 字段 | 说明 |
|------|------|
| 总数 | >60分个股的数量 |
| 盈利 | 盈利（收益率>0）的个股数量 |
| 亏损 | 亏损（收益率<=0）的个股数量 |
| 胜率 | `盈利 / (盈利 + 亏损) × 100%` |
| 最大盈利 | `max((T+2开盘价 - T+1开盘价) / T+1开盘价 × 100)%` |
| 最大亏损 | `min((T+2开盘价 - T+1开盘价) / T+1开盘价 × 100)%` |

> **注意**：统计对象是 **评分 > 60分的昨日选股结果**（即T-2日的选股），非全部选股。

#### b. A、B、C三组分别统计

以 **A、B、C 三组** 为分组维度（注意不是旧的B/C/D分组），每组展示：

- 该组个股数量
- 该组盈利只数
- 该组胜率（%）
- 该组平均收益率（%）

若某组在当日无候选股，则展示"该分组今日无数据"。

**分组定义**（沿用现有分组标准）：

| 分组 | 评分区间 |
|------|----------|
| A组 | `total_score < 60` |
| B组 | `60 <= total_score < 65` |
| C组 | `total_score >= 65` |

#### c. ReAct复盘部分

**保留不动**，维持当前ReAct复盘内容（Observe → Thought → Act 三闭环）的展示方式不变。

---

### 3.2 第5点调整需求

**展示结构改为：按 B、C、D 三组分别展示，每组按评分降序取 TOP3**

#### 分组定义

| 分组 | 评分区间 |
|------|----------|
| B组 | `60 <= total_score < 65` |
| C组 | `65 <= total_score < 70` |
| D组 | `total_score >= 70` |

#### 每组展示内容

每只候选股展示以下信息：

- 股票名称、代码
- 评分（total_score 分值）
- 来源（source 字段，如"涨停热点""大成交"）
- 各维度评分明细（筹码结构/资金接力/板块环境/趋势位置/大盘安全/位置评分）
- 换手率/封板备注（notes 字段）
- 风险提示（risks 字段）

#### 空分组与少股处理

- **空分组**：若某一分组当日无候选股，**保留该分组标题行**，并在其下显示文字说明："该分组今日无候选股"
- **不足3只**：若某一分组候选股数量小于3只，有多少展示多少，无需补齐
- **排序**：每组候选股**按评分（total_score）降序排列**

#### 移除内容

**取消** 当前报告第5点中"涨停接力 — TOP5"和"区间潜伏 — TOP5"的固定板块展示方式。

#### 保留内容

以下内容**保持不动**：

- 第5点头部信息：大盘状态、涨停总数、热点板块
- 评分说明
- 明日操作计划（含重点盯盘TOP3、交易纪律、持仓股关注）
- 重点盯盘TOP3的数据来源切换为**B/C/D三组汇总后取评分降序TOP3**（即不再从"涨停接力+区间潜伏"混合中取）

---

## 4. 验收标准

### 4.1 第4点验收

1. 标题正确显示为"4️⃣ T-2日选股涨跌及复盘"
2. 总体统计部分显示正确的6项指标（总数、盈利、亏损、胜率、最大盈利、最大亏损）
3. A/B/C三组分别统计展示，每组有数量、盈利、胜率、平均收益率
4. 若某组无数据，展示"该分组今日无数据"替代
5. ReAct复盘内容不变

### 4.2 第5点验收

1. 按B组、C组、D组三个分组展示候选股，每组标题清晰可辨
2. 每组候选股按评分降序排列
3. 空分组正确显示"该分组今日无候选股"
4. 不足3只的分组正常展示已有候选股
5. 已移除旧的"涨停接力TOP5"和"区间潜伏TOP5"板块
6. 第5点头部信息（大盘状态、涨停数、热点板块）、明日操作计划、交易纪律、持仓股关注**保持不变**
7. 重点盯盘TOP3的数据源切换为B/C/D三组汇总数据

---

## 5. 注意事项

1. **分组命名一致性**：第4点的分组为 A/B/C 三组，第5点的分组为 B/C/D 三组。两组互不冲突——前者是昨日选股的复盘分组（含<60分的A组），后者是明日候选按评分分组的推荐展示（仅展示>60分的B/C/D组）。
2. **数据来源**：第4点的统计口径（T+1开盘买入、T+2开盘卖出、>60分）需由SAAgent在技术方案中明确数据表来源和计算逻辑，本需求文档不涉及技术实现。
3. **ReAct保留**：第4点c部分"ReAct复盘"指当前 `react_report` 展示内容（无论是 `run_react_analysis` 的三闭环文本还是 fallback 的简版统计），**不做任何格式调整**。
4. **前端/Web对齐**：如果存在前端Web显示复盘报告的页面，后续需同步调整展示格式，本次需求范围仅限收盘任务生成的文本报告。
5. 需求文档评审通过后，流转至SAAgent编写技术方案，再由RDAgent进行开发。
