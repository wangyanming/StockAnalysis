# REQ-20260716-01-MySQL连接池改造

## 1. 背景

当前 `utils/dao.py` 中 `DB` 类使用全局单例模式（`get_db()`），内部维持单一的 `pymysql.connect()` 长连接。在 Web 服务（`web_server.py`）场景下，多个请求共享同一连接，出现以下问题：

- 某次查询异常（如 `Packet sequence number wrong`）导致连接损坏
- 后续所有 DB 请求复用同一损坏连接，全部报 `InterfaceError (0,'')`
- 前端表现：大盘概览板块排行/市场总结等全部 `Failed to fetch`、涨跌复盘/选股追踪全部 `Failed to fetch`

## 2. 需求

将 `DB` 类的单连接改为连接池，每个请求独立获取连接，使用后归还，避免单点故障。

## 3. 方案要求

### 3.1 连接池选型

推荐使用 `DBUtils.PooledDB` 或 `pymysqlpool`，优先 `DBUtils.PooledDB`（成熟稳定）。

### 3.2 接口兼容

- 对外暴露的 `get_db()` 函数签名不变 → 返回 `DB` 实例
- `DB.execute()` / `DB.fetchone()` / `DB.fetchall()` 方法签名不变
- 所有现有调用方无需改代码
- 新增 `DB` 应实现 `__enter__` / `__exit__` 上下文管理器，也支持 `with get_db() as db` 用法

### 3.3 连接池参数

| 参数 | 建议值 | 说明 |
|------|--------|------|
| `maxconnections` | 10 | 最大连接数 |
| `mincached` | 2 | 最小缓存连接数 |
| `blocking` | True | 无可用连接时阻塞等待 |
| `maxusage` | 1000 | 连接复用上限，达到后自动重建 |
| `charset` | utf8mb4 | 字符集 |
| `autocommit` | True | 自动提交 |

### 3.4 错误处理

- 查询失败时自动重试 1 次（重建连接后重试）
- 重试仍失败则抛出明确异常，包含 SQL 和参数信息

### 3.5 线程安全

连接池内部保证线程安全，Web 服务多线程场景下无竞态。

## 4. 影响范围

| 文件 | 改动类型 | 说明 |
|------|---------|------|
| `utils/dao.py` | 修改 | DB 类内部实现改为连接池 |
| `utils/dao.py` | 新增依赖 | 添加 `DBUtils` 或 `pymysqlpool` 依赖 |
| `utils/dao.py` | 新增 | 如果 `pymysqlpool`，需准备 pip 安装 |

## 5. 验证标准

1. `get_db()` 返回的 DB 实例可正常查询
2. 连续 10 次并发查询（同时发起的多线程请求）全部成功，无连接错误
3. 模拟连接损坏场景：手动关闭连接池中的一条连接，后续请求自动获取健康连接
4. 现有所有使用 `get_db()` 的地方无需修改代码即可正常工作
5. `bash tests/check_engineering.sh` 通过
