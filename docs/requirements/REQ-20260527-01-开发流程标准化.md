# 需求文档

**版本:** v1.0
**日期:** 2026-05-27
**状态:** 已定稿

---

## 1. 需求背景

- **提出人:** 主人
- **相关模块:** 基础设施
- **解决的问题:** 项目开发缺少标准化流程，需求变更、方案设计、代码修改、文档更新等环节没有规范约束，导致：
  - 经常遗漏文档更新
  - 改代码时不知道要看哪些上下文
  - 重复问题反复出现

## 2. 功能范围

### 2.1 做
- 建立 10 步开发流程标准
- 需求文档模板化 + skill 固化
- 方案设计文档模板化 + skill 固化
- 工程规范 skill 化（已有 engineering-rules skill）
- git hook 强制校验（已有 pre-commit）
- 文档保留历史版本（git 天然支持）

### 2.2 不做
- 不做项目管理工具集成（Jira/Trello）
- 不做文档自动排版/格式美化
- 不做代码评审流程

## 3. 详细说明

### 3.1 输入
主人提出需求（口头或文字描述）

### 3.2 输出
- `docs/requirements/REQ-*.md` — 需求文档
- `docs/design/DESIGN-*.md` — 方案设计文档
- `skills/` — 对应的 skill 定义

### 3.3 处理逻辑

```
需求提出
  ↓
[requirement-doc skill] 生成需求文档
  ↓
[design-doc skill] 生成方案设计
  ↓
[engineering-rules skill] 按规范开发
  ↓
[pre-commit hook] 提交前强制校验
  ↓
更新 PROJECT_STATE.md + MEMORY.md
```

### 3.4 边界条件
- 无需求文档不能进入方案设计阶段
- 无方案设计不能进入编码阶段
- 编码后 check_engineering.sh 失败不能提交
- 小修小改（改注释/变量名）不需要走全流程

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| **可追溯** | git log 可追溯每个需求的变更历史 |
| **可维护** | 模板支持扩展，不影响已有文档 |

## 5. 依赖关系

- **前置需求:** 无
- **外部依赖:** 无
- **配置项:** 无

## 6. 测试要点

- 说"写需求文档" → 自动按模板生成
- 已有文档时再触发 → 更新版本号
- 无对应需求文档时提方案设计 → 报错提示先写需求
