## 1. 背景与目的

### 1.1 背景

现有的收盘选股系统（`daily_pick_v2` / `daily_pick_v3`）在 **16:30 复盘时段** 执行，选出的候选股当天无法交易，需等待下一个交易日（T+1）买入，T+2 卖出。这导致两个问题：

1. **选股→买入的周期过长**：从 T日 16:30 到 T+1 开盘，期间存在隔夜消息面波动，选股信号容易失效。
2. **T+2 卖出有被套风险**：选股信号到卖出间隔约 2 个交易日，大盘突发下跌或板块退潮时容易被动持仓。

### 1.2 目的

新增 **盘中14:30选股模块**，完全独立于现有收盘选股体系：

- **缩短选股→交易周期**：14:30 选出 → 14:30-15:00（尾盘半小时）即可买入，当天建仓。
- **降低 T+2 被套风险**：T日买入 → T+1 即可卖出（T+1 制度下最短持仓周期），信号衰减时间窗口收窄。
- **盘中实时数据驱动**：不再依赖日线收盘数据，基于腾讯日K快照、同花顺板块实时、新浪指数实时等盘中数据做决策。

### 1.3 独立性约束

```
收盘选股（16:30）       盘中选股（14:30）
┌─────────────────┐    ┌─────────────────┐
│ stock_daily      │    │ intraday_stock   │  ← 独立新表
│ daily_limit_up   │    │ intraday_limit_up│  ← 独立新表
│ daily_sector     │    │ intraday_sector  │  ← 独立新表
│ index_quotes     │    │ intraday_index   │  ← 独立新表
│ daily_picks      │    │ intraday_picks   │  ← 独立新表
└─────────────────┘    └─────────────────┘
        不共享表、不共享数据、不共享逻辑
```

## 2. 功能需求

### 2.1 数据采集（5张表）

#### 2.1.1 `intraday_stock` — 个股行情快照

- **接口**：腾讯日K接口（`http://web.ifzq.gtimg.cn/appstock/app/fqkline/get` 或 `ifzq.gtimg.cn`）
- **数据量**：拉全市场 A 股（约 5000 只）
- **字段**：代码、名称、现价、涨跌幅、成交量、成交额、PE、总市值、流通市值、60日最高/最低、60日分位
- **采集时机**：14:30 开始时一次性拉取

#### 2.1.2 `intraday_limit_up` — 盘中涨停数据

- **接口**：同花顺或东方财富盘中涨停接口
- **字段**：代码、名称、现价、涨跌幅、涨停价、封板时间、炸板次数、封单额、所属行业、所属概念
- **用途**：过滤已涨停票、观察封板强度

#### 2.1.3 `intraday_sector` — 同花顺板块实时

- **接口**：同花顺板块实时行情
- **字段**：板块名称、板块涨跌幅、领涨股、板块内涨停数、板块成交额
- **用途**：筛选当日热点板块（涨幅前10）

#### 2.1.4 `intraday_index` — 新浪指数实时

- **接口**：新浪实时指数接口
- **字段**：指数代码、名称、现价、涨跌幅、成交量、成交额
- **代码**：`sh000001`（上证）、`sz399001`（深证）、`sz399006`（创业板）
- **用途**：判断大盘是否暴跌（非系统风险过滤）

#### 2.1.5 `intraday_picks` — 选股结果

- 存储每次14:30选股的候选结果
- 字段：日期、代码、名称、评分、各维度得分、所属板块、入选理由

### 2.2 选股逻辑

#### 2.2.1 候选池过滤链

```
全市场A股（~5000只）
  ↓ 过滤1：排除 ST / *ST / 退市 / 新股（上市<60日）
  ↓ 过滤2：排除已涨停（涨跌幅≥9.5%）
  ↓ 过滤3：排除已跌停（涨跌幅≤-9.5%）
  ↓ 过滤4：保留盘中涨幅在 3%~7% 区间
  ↓ 过滤5：所属板块热度（当日板块涨幅前10）
  ↓ 过滤6：PE 估值合理（PE>0 且 PE < 行业均值×2）
  ↓ 过滤7：位置安全（60日分位 ≤ 70%）
  ↓ 过滤8：大盘非暴跌（上证/深证/创业板 都 > -2%）
  ↓ ==========
  ↓ 候选池 → 评分排序 → TOP10
```

#### 2.2.2 核心选股方向

| 维度 | 筛选条件 | 说明 |
|------|----------|------|
| 涨幅区间 | 3% ≤ 当日涨幅 ≤ 7% | 既非涨停追高，又有日内动量 |
| 板块热点 | 所属板块当日涨幅前10 | 当天资金的进攻方向 |
| PE 估值 | PE > 0 且 PE < 行业均值×2 | 排除亏损股和高估泡沫 |
| 位置安全 | 60日分位 ≤ 70% | 不在顶部区间，有上行空间 |
| 大盘安全 | 主要指数跌幅 < 2% | 系统性风险回避 |
| 排除规则 | 非ST/非新股/非涨停/非跌停 | 基础安全过滤 |

#### 2.2.3 评分模型

每个候选股按以下维度综合打分（满分100）：

| 维度 | 权重 | 说明 |
|------|------|------|
| 日内强度 | 30分 | 涨幅位置（3-7%范围内，越靠近4-5%越优）+ 量比（0.8<量比<2.0） |
| 板块热度 | 25分 | 所属板块在全市场板块中的排名（前3得满分，4-10得分递减） |
| 估值安全 | 20分 | PE在合理范围内的越低越优，PB<3 + PE<30 加分 |
| 位置评分 | 15分 | 60日分位 30%-60% 区间最优（过低有趋势风险，过高有顶部风险） |
| 大盘环境 | 10分 | 大盘涨跌正常（-1% ~ +0.5% 得满分，超出区间扣分） |

### 2.3 入库要求

- **5张独立表的数据全部入库**
- 基础数据（stock/limit_up/sector/index）先入库，再以入库后的数据执行选股
- 选股结果写入 `intraday_picks`
- 保留历史记录，后续可回溯分析

### 2.4 通知格式

盘中14:30 选股只输出 **候选股列表**，不要复盘报告。格式示例：

```
📊 盘中14:30 选股结果（2026-07-09）

────────────────────────────

─── 候选股 TOP5 ───

1️⃣ 002xxx 某某科技
  💹 现价 12.45 | 涨幅 +4.78% | PE 22.3
  📌 所属：AI算力（板块排名 #2）
  📊 位置：60日分位 45% | 量比 1.32
  🏷️ 选入理由：AI算力板块前排+涨幅适中+位置安全
```

## 3. 非功能需求

### 3.1 性能

| 指标 | 要求 |
|------|------|
| 数据采集完成 | 14:35前（全量数据拉取，5分钟内完成） |
| 选股计算完成 | 14:38前（选股逻辑简单，无需复杂计算） |
| 通知发出 | 14:40前 |
| 数据采集并发 | 全量个股支持并发拉取 |

### 3.2 可观测性

- 每个环节（采集→入库→选股→通知）打印日志
- 失败环节可独立重试
- 总耗时上报

### 3.3 独立性

- 模块自身包含数据采集、数据入库、选股逻辑、通知输出的全部能力
- 不引用 `core/analyzer/daily_pick_v2.py` 或 `daily_pick_v3.py` 的任何函数
- 不写入 `stock_daily` / `daily_limit_up` / `daily_sector` / `daily_picks` 等收盘表

### 3.4 错误处理

- 数据表不存在时自动创建
- 单只个股拉取失败跳过不影响整体
- 指数数据拉取失败时视为大盘安全（保守策略）
- 板块数据拉取失败时回到基础涨幅筛选（降级）

### 3.5 cron 配置

```
工作日 14:30 执行（仅在周一至周五）
14:28 * * * 1-5  (预检查：确认数据库可达、数据源可达)
14:30 * * * 1-5  (主流程：采集→选股→通知)
```

## 4. 验收标准

| # | 验收项 | 验收方法 |
|---|--------|----------|
| 1 | 独立脚本可执行 | `python scripts/intraday_pick_1430.py` 正常运行 |
| 2 | 5张表自动创建 | 执行后 `SHOW TABLES LIKE 'intraday_%'` 返回5张表 |
| 3 | 全量个股采集 | `intraday_stock` 表记录数 > 4500 |
| 4 | 热点板块识别 | `intraday_sector` 有当日板块排行 |
| 5 | 选股结果非空 | `intraday_picks` 有候选记录（正常交易日） |
| 6 | 大盘暴跌时跳过 | 上证/深证/创业板任一 ≤ -2% 时输出"大盘风险，今日不选" |
| 7 | 不依赖收盘表 | `SELECT * FROM daily_picks WHERE ...` 不变（盘中不写收盘表） |
| 8 | 可选股输出 | 不输出复盘报告，只有候选股列表 |
| 9 | 错误日志 | 采集/选股/入库各环节均有日志输出 |
| 10 | 工程规范 | `bash StockAnalysis/tests/check_engineering.sh` 通过 |

## 5. 术语表

| 术语 | 说明 |
|------|------|
| 60日分位 | 当前价格在60日价格区间的位置 = (现价 - 60日最低) / (60日最高 - 60日最低) × 100% |
| 板块涨幅前10 | 全市场同花顺行业板块/概念板块中，当日涨幅排名前10的板块 |
| 大盘暴跌 | 上证指数、深证成指、创业板指任一跌超2%视为系统风险 |
| 量比 | 当前成交量 / 过去5日同时段平均成交量 |
